# 里程碑机制 · 写在队列里的 `## 里程碑 MSn`

> 回答一件事：**长任务怎么分段、什么时候停下来让人验收、验收之后怎么继续。**
> 按需读：排任务前读 §1~§2；排查"为什么不往下走了"读 §3；改门禁读 §4。

## 0. 什么时候插（**不另建计划文件**）

| 规模 | 做法 |
| --- | --- |
| ≤ 16 条、一个阶段能干完 | **不插里程碑**，排 1~2 批做完，走普通收尾 |
| > 16 条，或明显能切成几段 | 在**同一份队列**里每 8~12 条之后插一个里程碑节点 |

为什么门槛是 16：节点太密（每批都停）会让人开始无脑点"继续"，关卡退化成噪音；
而任务不大时，那一眼的代价比它能防的风险更高。

## 1. 格式（解析锚点就是这两行）

```markdown
## 里程碑 MS1 · 横屏 HUD
- 验收：`npm run test:hud`
- 确认：已验收 · 批次 `20261023-1018`     ← 只在**真的收到用户答复**之后写
```

- `## 里程碑 ` + `MS<n>` 是解析锚点；`· <名字>` 给人看；
- `- 验收：` 是硬停时要跑的命令（**每个里程碑都必须有**，没有时门禁判红）；
- `- 确认：` 是"人验收过"的凭证。**替用户写它 = 自己给自己验收**；
- 节点之间的普通条目照旧：`- [ ] [T12] …` + 下方 `验证：` 凭证。

## 2. 判定顺序（钩子每轮只看一处）

1. 有 `[~]` → 继续它；
2. 否则取第一条 `[ ]`（`[发现]` 排后面）；
3. **在递出这条之前**先看里程碑：若它前面还有 `[ ]` / `[~]`，说明还没到点，正常递；
4. 前面的条目全部 `[x]` / `[阻塞]`（未完成的 `[发现]` 不算——它排在选择顺序后面，
   若算进去会让关卡被绕过）、而该里程碑**没有确认行** → **硬停**，不递后面的任务。

"到点"是**做完它前面那一段**才停，不是"取到节点就停"——否则永远差一条，关卡从不触发。

## 3. 硬停之后（三选一，只有"继续"才动队列）

1. 真跑 `- 验收：` 的命令，把输出贴给用户；跑不起来就如实写"未验证"，**不编结果**；
2. 弹窗问用户：**继续下一段** / **调整队列** / **先收在这里**（队列头改 `> 状态：讨论中`）；
3. 只有选"继续"之后才：
   - 在 `## MSn` 小节补 `- 确认：已验收 · 批次 <旧号>`；
   - 收尾**本段**（DONE / OVERVIEW / TASKS / TIPS；**先不归档队列**）；
   - 跑 `node .continue/hooks/queue-init.mjs --new-batch` 换 `> 批次：`；
   - 删掉本段已完成的 `[x]` 条目（它们已经进了 `DONE.md`），保留里程碑与后面的条目；
   - 直接开始下一条，不要来问"要不要继续"。

最后一个里程碑确认后，队列里没有待办了 → 钩子下发**正常五步收尾**（这时才归档队列文件）。

## 4. 门禁（`npm run audit:docs` / `check.mjs`）

| 查什么 | 不查的后果 |
| --- | --- |
| 里程碑必须有 `- 验收：` | 硬停到它时只能空手问人 |
| 里程碑 id 唯一 | 两个节点同名，确认行挂错对象 |
| 确认行里的批次号在 `notes/batches.md` / `DONE.md` / `doing/` 里存在 | 回溯链断：查不到那一段是哪批做的 |
| 确认行前面不能还有未完成条目 | 没做完就"验收"，关卡白设 |
| `queue-init.mjs` 的注入里仍有里程碑段 | 重装框架改回旧版，机制无声消失 |
| `doing/*-plan.md` 不能残留 | 旧计划会被当成"另一个会话的队列" |

## 5. 机器管不到的

- **该不该插**：16 条是开工前的估计，真的只干了 6 条机器不报，只能靠人看一眼；
- **里程碑够不够"用户价值"**：门禁查得出"有没有验收命令"，查不出"这一段是否值得单独验收"；
- **该勾没勾**：钩子只查"确认行有没有批次号"，查不出"做完了但忘了确认"。

## 6. 与旧版"计划文件"的区别（已移除）

旧机制是 `doing/<会话ID>-plan.md`（里程碑 → 阶段 → 每阶段一批），队列被反复重置。
它和队列表达的是同一件事的两份副本，顺序 / 批次 / 状态必然漂；所以现在把节点直接写进队列，
绑定问题、孤儿计划、`--plan` 归档参数都不存在了。旧文件由 `migrateLegacyLayout()` 自动归档到
`logs/<会话ID>/plan.md`。
