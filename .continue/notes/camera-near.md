## 贴脸透视有两条独立路径，只堵一条不算修完

- 症状：进山洞 / 卡进石头里"看到一个透明半透明的世界"。
- 根因两条，处置也分两条：
  1. **近裁面切掉了眼前的面**（相邻实心格之间那面是背向剔除的，一裁掉就没有东西挡着）。
     `CAMERA_NEAR = 0.25` 的前提"最近的面也在 0.5 格外"不成立——眼在脚底 +1.62，
     头撞天花板（两格高的洞里跳一下）时只剩 **0.18**。
     处置：`render/cameraNear.ts` 每帧按**相机位置**（不是眼睛——第三人称被墙压到眼前
     那一档 `clampedCameraDistance` 会返回 0）量到最近碰撞盒的距离，
     `near = clamp(间隙 − 0.05, 0.02, 0.25)`，旁观模式不收缩。
  2. 相机**真的**进了实心方块（沙子砸头 / 活塞推 / 传送落点）——那面是背面、已被剔除，
     **near 调到多小都没用**。处置：改上 `suffocate` 整屏色罩（颜色取该方块贴图的平均色）。
- 三个易错点：
  - 判据要用**碰撞盒**而不是"非空气格"：水 / 岩浆 / 火 / 藤蔓 / 蛛网没有碰撞盒，
    不该把 near 拖下来；非完整方块要按**局部盒**算距离，否则半砖那档会误判
    （按整格盒底算出 0 = "埋在里面"，按整格顶面算出 0.73 = 漏判）。
  - `camera.near` 改完**必须** `updateProjectionMatrix()`，否则画面不变。
  - 别在 `applySettings` / `setViewDistance` 里写 near —— 那两处只管 `far`，
    写死会覆盖掉每帧的收缩。
- 别再往回走的三条：全局把 near 降到 0.15（白丢批次 520 的深度精度，且埋在方块里照样透视）、
  给区块材质关背面剔除（多一倍三角形，手机崩帧）、压低玩家眼睛高度（为渲染改玩法数值）。

## 浏览器 e2e：单格 `/setblock` 埋不住玩家，要 `/fill` 整块填

- 症状：脚本里 `/setblock ~ ~1 ~ stone` 之后读相机所在格，方块 id 是 0、色罩也没生效。
- 根因：物理会把**卡在方块里**的玩家挤到旁边的空格（单格有邻居可逃），相机就不在方块里了。
- 处置：验"被埋住"这类状态用 `/fill ~-2 ~-1 ~-2 ~2 ~3 ~2 <方块>` 整个埋起来（没有可逃的邻居，
  玩家留在原地）。另外三条同场踩到的：
  - `sand` 是重力方块，`/fill` 完就掉下去了，要测黄色用 `sandstone`；
  - `/setblock` 只在创造模式可用，生存模式会回一句"只能在创造模式下使用"却看起来像成功
    （`runCommand()` 的返回值要打出来看）；
  - headless 下 rAF 只有 ~7fps，靠 rAF 每帧"钉住玩家位置"会与物理抢帧（读到的是物理跑完之后的
    值），要造**能持续保持**的状态（例如创造飞行顶住天花板）再采样。
