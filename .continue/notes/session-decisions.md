# 决策留底 · `doing/<会话ID>-decision.md`

> 回答一件事：**AI 自己拍板的地方，怎么让事后的人看得懂、能复核。**
> 按需读：写决策前读 §2；改门禁读 §3。

## 1. 为什么有这个文件

用户给的规则是：**需要拍板的地方，以 AI 的意见为准，不再逐条弹窗**。
但"不问"必须配"留痕"，否则事后没人知道哪一步是替人做的、依据是什么——那等于把决策从
"两个人商量"变成"一个人猜"，出错时连复盘入口都没有。

所以它和队列 / 计划是同一类东西：**正在做的文件**，收尾时加时间戳归档进 `logs/<会话ID>/`。

## 2. 格式

```markdown
## D1 · <一句话说清这是个什么决策点>

- 决定：<选了哪个方案>
- 为什么：<依据 + 哪里不确定；写"我知道什么、我不知道什么">
- 影响：<改了哪些文件/行为；能不能撤回；别人接手要注意什么>
```

三条硬要求（前两条门禁会判红）：

| 要求 | 为什么 |
| --- | --- |
| `- 决定：` | 没有它，读者不知道你到底定了什么 |
| `- 为什么：` | 只留结论、没留依据 = 没法复核，下次同款决策还得重新想一遍 |
| `- 影响：` | 让人一眼看到"这一步退不回去"——尤其是删数据、改格式这类 |

写得"能看懂"的标准：**把当时的两个候选都写出来**，再说为什么选了这个。
只写"我选了 A"等于没写。

## 3. 门禁（`npm run audit:docs`）

| 查什么 | 不查的后果 |
| --- | --- |
| 文件名必须是 `<会话ID>-decision.md`，且那个会话的队列还在 | 孤儿文件 = 收尾时没一起归档，下次分不清它属于哪轮 |
| 至少一条 `## D<n>` | 建了文件却一条没记 |
| 每条都有 `- 决定：` / `- 为什么：` | 见上表 |
| ≤ 300 行 | 决策笔记不是台账，超了说明该合并同类项 |

## 4. 归档

收尾第五步：`node .continue/hooks/archive-queue.mjs <会话ID>` 归档队列，
若写过决策记录再跑 `--decision`（不带 flag 时会一起搬）。两份同一套命名：
`logs/<会话ID>/queue.md` / `decision.md`——**按会话分目录、累积式**（新批次插到最上面、`----------` 分隔），
文件名里不再重复会话 ID（目录已经说了）。都在 `.continue/logs/` 下（gitignore：本机可查，不进仓库）。
