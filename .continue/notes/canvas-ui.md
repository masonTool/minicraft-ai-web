## 1. 现状：三层，不是两层

```
core/   410 个 .ts   世界模拟 / 规则 / 背包 / 合成 / 命令 / 联机协议   ← 基本零 DOM
render/ 33 个 .ts    WebGL2 + three.js 的 3D 世界
ui/     49 个 .ts    DOM 界面（约 2.1 万行，InventoryScreen 独占约 7,600 行）
        index.html   内联 CSS 约 5,700 行（设计令牌 / 原版配色 / 横屏断点 / 层叠约定）
        main.ts      约 2.06 万行（主循环 + 输入 + 一部分 HUD 接线）
```

**关键事实**：游戏逻辑本来就不在 DOM 里（全仓 `document.` 在 `core/` 只出现在
`I18n.ts` / `webglSupport.ts` / `ClientId.ts` / `hostCore.ts` 四个文件，都是环境探测）。
所以"搬到 canvas"= **重写界面层**，`core/` 一行不用动。

## 2. 路线：独立 2D canvas 覆盖层（不是塞进 WebGL）

| | A. 2D 覆盖层（**选它**） | B. 进 WebGL（正交相机 + 精灵批处理） |
| --- | --- | --- |
| 文字 | `fillText` 直接用系统字体 | 必须 SDF/MSDF 字形图集（含中日韩 = 动态图集） |
| 6 语言 | 零字体资源 | 构建期扫文案 + 运行期扩图集 |
| 调试 | 浏览器里能直接看/截图 | 基本靠肉眼 |
| 移植到原生 | 一般 | 最好 |

选 A 的唯一决定性理由：**文字**。B 的收益（一张纹理、一批四边形）只在"确定要出原生/主机版"
时才成立；在此之前，字形图集的成本会让整个迁移变成另一个项目（见决策 D1、D2）。

## 3. 目录与依赖方向

```
src/ui2d/
  text.ts      字体栈 / 测量缓存 / 分词 / 截断 / 折行 / drawText     ← 纯函数，离线可断言
  input.ts     hitRegionAt（纯函数） + Ui2DInput（指针路由）
  overlay.ts   2D 覆盖层：DPR、尺寸、清屏、销毁
  widgets.ts   画法：圆角矩形 / HUD 底板 / 进度条 / 原版按钮
  Hud2D.ts     组合：收状态 → 画（当前只有阶段 0 的三样）
  index.ts     汇总入口
```

依赖只能往下走：`面板/Hud2D → widgets/overlay → text/input`。
**禁止**反向依赖 `main.ts`，也禁止依赖 `ui/` 里的 DOM 组件（唯一例外 `ui/Device.ts`）。
这条约束是"将来整层换后端"的前提：`Hud2D` 只认 `Ui2DOverlay` 暴露的
`context + width/height`，换后端时改一个类。

## 5.1 已落地（阶段 1.5：快捷栏）

阶段 0 那三样（红闪 / Boss 条 / 破坏与进食进度）**选得对但看不见**：它们都是
"事件发生时才出现"的浮层，正常玩的时候屏幕上什么都没有，用户的原话是
"改的这几个地方都不太明显，看不出来效果如何"。于是 1.5 换成每帧都在眼前的快捷栏。

- `src/ui2d/Hotbar2D.ts`：面板（`#c6c6c6` + 3px 斜面 + 2px 黑描边）、9 个格子
  （`#8b8b8b` + 2px 斜面）、图标、数量（12px 四向描边）、序号（10px）、
  耐久条（3px 三档）、选中格（白框 + 半透明白底 + 上抬 2px + 放大 1.08 + 柔光）。
- **几何不抄常量**：输入是 `getBoundingClientRect()` 量出来的面板与格子矩形
  （相对覆盖层），所以断点、`env(safe-area-inset-bottom)`、转屏后的尺寸全自动跟上。
- **快照缓存**：状态签名不变时每帧只 `drawImage` 一次；换槽/捡东西/掉耐久/转屏才重建。
- **命中仍借 DOM**：`.slot` 设 `opacity: 0`、`#hotbar` 自己的底/斜角/描边设成透明
  （边框宽度保留，免得两侧按钮位移），点击与长按提示走原来那条绑定。
  ⚠️ 不能用 `visibility: hidden` / `display: none` —— 那样格子不再参与命中，
  `bindHotbarTouch` 与长按看物品会一起失效。
- 断言：`tests/ui2d.test.ts` 34 条（新增 12 条：内容盒 / 图标居中 / 数量与序号锚点 /
  耐久轨道与比例 / 选中格的缩放与上抬 / 快照原点 / 签名稳定性）。

## 5.3 调试遮罩：一块黄色告诉你"这块是谁画的"

`?ui2d=1&ui2dtint=1`（只在 `ui2d` 打开时生效）。屏幕上**每一块黄色的地方就是 canvas 画的**，
其余颜色来自 DOM / WebGL。预览页同理：`tools/preview/hotbar.html?tint=1`、
`tools/preview/hud.html?only=boss&tint=1`。

- 实现只有一句（`ui2d/debug.ts`）：所有绘制结束后把 `globalCompositeOperation` 切成
  `source-atop`，整块刷一层半透明黄 —— 合成器只染"**已经有像素的地方**"，
  于是不用维护"这一帧画了哪些矩形"，将来新增控件自动被覆盖。
- 为什么需要它：迁得对的时候**外观与 DOM 一模一样**，看的人根本分不出哪块换了
  （阶段 0 的教训，用户原话"改的这几个地方都不太明显"）。遮罩把"进度"从
  "肉眼比像素"变成"数黄块"。
- ⚠️ 三条边界：① 只是调试开关，**不进设置页**；② **不跟 `ui2d=1` 绑定** ——
  多一次全屏填充会让帧率 A/B 失真，颜色也不对，真机验收时容易被当成 bug；
  ③ 它是"整层"的，同屏多样东西时看不出哪块对应哪个控件（要点名得另加标签，本批不做）。
- 一个反直觉但正确的现象：**红闪打开时整屏都是黄的** —— 因为红闪本身就是全屏 canvas 填充，
  遮罩忠实地把整层都染了。

## 6. 判定不搬 / 搬法特殊（写清楚，免得下次重新踩）

| 东西 | 结论 | 原因 |
| --- | --- | --- |
| **准星** `#crosshair` | **不搬**（阶段 0 已排除） | 靠 `mix-blend-mode: difference` 与下层画面差值混合，属于 DOM 合成器能力；2D canvas 的 `difference` 只在本图层内合成，叠到 WebGL 上就是白十字，浅色场景反而看不见。真要搬：单独一张 canvas 并保留那条 CSS。 |
| **文本输入**（聊天/告示牌/铁砧/搜索/世界名） | **DOM 必须留** | canvas 无法唤起系统输入法（IME）。方案：**隐藏 `<input>/<textarea>` 收字 + canvas 显示**，自己处理 composing 下划线、光标、选区、粘贴。`ui/Keyboard.ts` 的 `--kb-inset`（键盘不挤压画面）要在 canvas 版重新对齐。 |
| 长按/拖拽/连发 | 搬（阶段 4） | 现在靠 DOM 元素级 pointer 事件 + 定时器；canvas 里要自己记"按下的是哪个区域、手指移出即取消"（`Ui2DInput` 已经按这个语义写）。 |
| **快捷栏的点击/长按**（阶段 1.5） | **画在 canvas、命中仍走 DOM**（过渡） | 覆盖层的 `pointer-events` 是**元素级**的：铺满全屏，打开就吃掉 `#touch-look` 的视角手势。区域级穿透要等阶段 6 重做手势层，这一批不值得冒险 —— 所以格子设 `opacity: 0`（**不是** `visibility: hidden`，那会连命中一起关掉）。 |
| 原生控件（`<select>`、滚动条、tooltip 的 title） | 搬（自己画） | 没有等价物；下拉要挂到最上层避免被裁切（DOM 版挂 `body` 也是这个原因）。 |
| 无障碍（`role` / `aria-label` / 键盘 Tab） | **会退化** | canvas 对读屏是一张图。缓解：保留一层不可见的镜像节点（`aria-hidden` 之外），或至少在开关打开时给出可访问的替代入口。这条要写进发布前的检查表。 |
| 全屏 / 剪贴板 / 文件下载 / 指针锁 | DOM API 不变 | 这些本来就不是"绘制"，`ui/Fullscreen.ts` 等模块继续用。 |

## 7. 迁移 checklist（每个面板都要过一遍）

1. **色值只抄不猜**：`widgets.ts` 的 `PALETTE` 与 `index.html` 的 `--mc-*` / `--hud-*`
   必须一一对应；改一处要同步另一处（迁移期两边并存，色漂是最难发现的一类回归）。
2. **文案必须走 `t()` / `tp()`**：canvas 没有 `textContent` 给 i18n 审计扫，
   所以 `audit:i18n` 看不到的漏翻会直接画到玩家脸上。新面板的文案一律先进 `locales/`。
3. **绘制单位是 CSS px**：不要自己乘 DPR（`overlay` 已经 `setTransform`）。
4. **`pointer-events` 默认关**：只有真有可点区域时才打开（`Ui2DInput.setRegions` 自动做），
   否则铺满全屏的层会吃掉触摸端的视角手势。
5. **手机横屏是第一场景**：所有断点先在 844×390 下看，再回去看 PC。
6. **关掉开关必须能完全回退**：每个面板迁移时保留 DOM 实现，直到该阶段真机验收通过再删。

## 8. 门禁与测试改写（这条最容易被低估）

- `tools/ui-test.ts` 约 **6,400 行**断言，其中很大一撮是**对源码文本与 CSS 做字符串匹配**
  （例如"设置行容器不再用 label"、"dropdown 必须挂 body"、`index.html` 里的某条样式）。
  面板一旦搬到 canvas，这些断言会**成片变红**，而且红的原因不是功能坏了。
- 处置顺序：**先加新的**（对 `Ui2DOverlay` 的绘制描述 / 布局纯函数做断言），
  **再删旧的**（DOM 实现删除的同一次提交里删掉对应断言）。不要先删后加 —— 中间那段空窗期
  等于没有回归保护。
- 阶段 0 已经示范了正确的粒度：把"排版决策"（折行/截断）与"几何换算"（Boss 条宽度、
  进度条位置）做成纯函数，断言打在这两处，而不是打"某一个像素长什么样"。

## 9. 现在的风险清单

1. **真机帧率未知**（最大风险）：DOM 合成层 vs 多一张全屏 canvas，谁更便宜要在真机上量。
2. **输入法**（阶段 3 的硬骨头）：隐藏 input 的光标/选区/composing 体验，安卓各家 WebView 差异大。
3. **背包交互**（阶段 4）：4 天能过、8 天也正常；它的交互全是点/拖/长按/连发的组合。
4. **门禁红灯期**：阶段 2~5 期间 `ui-test` 会持续有失败项，必须"边迁边绿"，不能攒到最后。
