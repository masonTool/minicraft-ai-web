# 跳一跳（替换推箱子 / 打砖块）· 总纲

> 状态：**执行中**（2026-10-23 定稿）。J0 已开工，J1~J4 按阶段开新批次。
> 本文件只写「做什么、为什么、边界、门槛」，**不记进度**（进度在 `DONE.md` 与 `doing/`）。
> 需求来源：用户 2026-10-23 口述——去掉两个 2D 游戏，做「跳一跳」，用现有方块材质（雪地/草地）与自捏方块人，靠压缩身体蓄力起跳。

## 0. 一句话

主菜单「小游戏」里只留一个**无尽模式**的跳一跳：横屏铺满画面、按住蓄力、松手起跳、落在方块上得分、掉下去结束，最高分存本地。

## 1. 总目标（Definition of Done）

1. 「小游戏」→ 卡片 → **直接开局**（不再有选关页）。
2. 横屏 640×360 ~ 950×430 下：当前+下一方块占屏宽 ≥55%，人物高 ≥屏高 20%。
3. 按住蓄力（身体压缩 + 方块下压 + 音调上升），松手起跳（翻转 + 落地回弹）。
4. 方向自动对准下一方块，玩家只控距离；普通落点 +1、中心 +2/+4/+6…（封顶 +32）、掉落结束。
5. 特殊方块：音乐盒 +30、魔方 +10（停留 2 秒）。
6. 难度随分数递增（方块变小、间距变远），但间距**永远 ≤ 最大蓄力可达距离**。
7. 结算：本局分数 / 最高分 / 再来一局 / 退出；最高分落 `localStorage: mc.minigame.v2`。
8. 退出后 DOM 清空、几何与纹理回落到进之前（`npm run minigame:perf`）。
9. 门禁：`npm run check` 全绿、`build:fast` 出包、`guard` 0 错误、E2E 全绿。
10. 真机手感由用户确认（唯一需要人参与的门槛）。

## 2. 原版 vs 我们的版本（差异台账）

| 维度 | 原版 | 我们 | 原因 |
| --- | --- | --- | --- |
| 屏幕 | 竖屏 | **横屏** | 本项目手机端就是横屏（640~950×360~430） |
| 视角 | 等距 2.5D | **真 3D 斜俯视**（FOV 50°） | 要复用方块材质与方块小人；玩法仍是"一个自由度"的 2.5D |
| 行进方向 | 屏幕右上 | **屏幕左下 → 右上（横向为主）** | 横屏宽度富余、高度只有 360~430 |
| 人物 | 白色无脸小人 | **玩家自捏方块人**（`PlayerRenderer`） | 代入感 |
| 方块材质 | 固定彩色 | **每局一个主题**（草地 / 雪地 / 沙漠 / 石山，按 seed 取） | 复用现有素材；一局内不切主题，避免结算画面突变（实测很难看） |
| 连击封顶 | 说法不一（+20 / +32） | **+32** | 高分更有 chase 感 |
| 特殊方块 | 井盖+5 / 魔方+10 / 便利店+15 / 音乐盒+30 | **先做 2 种**：音乐盒 +30、魔方 +10 | 控制范围，跑通后再补 |
| 力度提示 | 无（靠手感 + 音效） | **细力度条（可在设置里关）** | 低龄友好 |
| 关卡 | 无尽 | 无尽 + 最高分 | 与原版一致 |
| 音效 | 有（蓄力音、落地音等） | **WebAudio 合成**，不引入素材文件 | 不增加包体 |

> 与原版不一致的地方都记在这张表里；"和原版不一样"本身不是 bug，**没有登记的差异才是**。

## 4. 参数表（初值，集中在 `src/minigame/games/jump/config.ts`）

| 参数 | 初值 | 说明 |
| --- | --- | --- |
| 最大蓄力时长 | 0.9 s | 按满 = 最大距离 |
| 最大跳跃距离 | 4.5 格 | 间距上限 ≤ 4.2，保证可达 |
| 蓄力→距离 | 线性 | 最好预测，不做缓动 |
| 方块边长 | 2.0 → 0.9 格（0→60 分线性） | 难度来源之一；必须小于最小间距，否则柱子重叠 |
| 方块间距 | 2.6 → 4.2 格（下限随分数抬到 3.0） | 难度来源之二；**下限 > 方块边长**（1.4/1.8 时实测整屏只有一根柱子） |
| 生成方向 | −30° / 0° / +30° 三选一 | 自动对准，避免连续同侧过多 |
| 中心判定 | 距中心 ≤ 半边长 × 0.22 | 对应原版白圈手感 |
| 连击 | +2/+4/+6… 封顶 **+32** | 断链重置为 +2 |
| 特殊方块 | 10 分后出现，概率 12%，不连续 | 音乐盒 +30、魔方 +10 |
| 相机 | FOV 50°、距 6.5 格、俯角 38° | 横屏构图初值 |
| 人物压缩 | `scale.y = 1 − 0.35 × charge` | `PlayerRenderer.object` 原点在脚底，压缩不会陷进方块 |
| 方块压缩 | `scale.y = 1 − 0.08 × charge` | 原版细节 |

> 这些是**起点**，J3 用 `tools/jump-balance.ts` 模拟 1000 局后按结果调；J4 只做真机细调。

## 5. 架构

```
src/minigame/
  types.ts          # 契约（复用，不动）
  MiniGameHost.ts   # 生命周期 / DOM / 异常 / 转场（复用，不动）
  catalog.ts        # 单游戏目录（改）
  progress.ts       # 最高分（改，v2）
  games/jump/
    config.ts       # 全部可调参数（唯一来源）
    logic.ts        # 纯逻辑：生成器 / 蓄力距离 / 落点 / 计分 / 难度曲线
    pillars.ts      # 纯逻辑：柱子按"三张贴图组合"分组（可离线断言）
    PillarScene.ts  # 柱子渲染（顶/侧/底三套 UV）+ 相机跟随
    themes.ts       # 群系主题（一局一个，按 seed）+ 天空渐变
    scene.ts        # 画面 / 输入 / 状态机 / 动画 / HUD / 结算 / 音效
```

- 小游戏**不碰 `World` / 存档**；只拿 `renderer`（只读）+ `atlas` + 自己的 DOM 层。
- `PlayerRenderer` 复用：`new PlayerRenderer(scene, () => 1)`（全亮），外观取 `loadSettings()` → `paletteOf()`。
- 主菜单路径自建 canvas + renderer（App 未创建），退出全部 `dispose()`（沿用现有做法）。
- 测试钩子：`window.__minigame`（`id / status / score / charge / blocks` 只读），供 E2E 断言；风格与 `__worldMenu` / `__mc` 一致。

## 6. 核心判定（纯函数，离线可断言）

```
方向 u = normalize(next.center − current.center)      # 自动对准
距离 d = min(dMax, v × charge)                        # 蓄力线性
落点 P = C + u × d

命中： |P.x − N.x| ≤ half && |P.z − N.z| ≤ half
中心： |P − N| ≤ half × 0.22
否则： 掉落 → 本局结束
```

难度曲线保证可达：`gapMax(score) ≤ dMax − 0.3`。

状态机：`Idle → Charging → Airborne → (Landed → Idle | Falling → Over → Idle)`。

## 8. 风险与对策

| 风险 | 对策 |

## 9. 判定不做

- **不做排行榜 / 账号**：只有本地最高分（与旧进度同一口径）。
- **不做选关 / 关卡编辑**：无尽模式，不做 UGC。
- **不做 4 种特殊方块的首发**：先 2 种，跑通后再补（补的时候更新 §2 差异表）。
- **不做联机 / 好友对比**。
- **不改主世界任何数据链路**：小游戏仍是一层 DOM + 独立 scene。
