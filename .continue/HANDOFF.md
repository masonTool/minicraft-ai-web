# 接手必读 · 队列机制（.continue/）

> ⚠️ **本文件讲的是"任务队列怎么跑"**；项目本身的状态与历史在**仓库根** [`HANDOFF.md`](../HANDOFF.md)。
> 两者的分工：根 `HANDOFF.md` = 做到哪了、踩过什么坑；本文件 = 队列怎么排、钩子怎么认、收尾怎么算。
>
> 队列在 `.continue/queues/<session_id>.md`，长期规划在仓库根 `TASKS.md`，历史在 `.continue/DONE.md`
> 与 `.continue/archive/`。

## 1. 队列与标记

每个会话一份：`.continue/queues/<session_id>.md`。文件名必须与会话 ID 一致——钩子只靠 ID 推导路径。

| 标记 | 谁写 | 含义 |
| --- | --- | --- |
| `- [ ]` | AI | 待办（规划时写） |
| `- [~]` | AI | **进行中**（开始做这条时自己改） |
| `- [x]` | AI | 完成 |
| `- [阻塞]` | **钩子** | 卡住：连续 5 轮没做完被隔离，等用户决策 |
| `- [ ] [发现]` | AI | 干活时撞见的新问题，最多 5 条，必须写证据 |

`[~]` 表示"**正在做**"，不是"跳过"；跳过/放弃没有标记，走"回复里说明 + 用户决定"。
早期版本用过 `[-]` 表示进行中，已废弃——同一个意思不留两套符号。

头部两态（**只认文件前 5 行**，正文里提到这几个字不算）：

- `> 状态：执行中` —— 钩子开始递任务；
- `> 状态：讨论中` —— 放行不递任务（还没和用户确认方案时用）。

规则：

1. 讨论阶段不要建队列；要动手时才建，每条都要能独立验证、能单独提交。
2. 一次只做一条：开始做时把 `[ ]` 改成 `[~]`，做完改 `[x]`。
3. **收尾要用户确认**：`[ ]` / `[~]` 都没有了 → 先请用户确认；确认后一次性做三件事：
   整份队列写进 `DONE.md`（含 `[阻塞]`，附完成说明）、`TASKS.md` 对应条目改成 `[x]`、删掉队列文件。
4. **长期待办写在仓库根 `TASKS.md`**（它由 `npm run audit:tasks` 核对，是全项目唯一的总表）；
   `.continue/TASKS.md` 只放"马上要排进队列的几条"，默认空。
5. 不停下来等确认；遇到困难自己解决并把结论记下来（收尾确认那一步除外）。
6. `[阻塞]` 只有钩子写，AI 不写也不删；判断某条不该做时在回复里说明理由，交用户决定。

## 3. 钩子怎么工作

四个脚本注册在 `.codebuddy/settings.json`（**相对路径**，换机器不用改）：

| 事件 | 脚本 | 做什么 |
| --- | --- | --- |
| UserPromptSubmit | `queue-init.mjs` | 每个会话**第一次**收到消息时，注入会话 ID 与队列路径；之后静默 |
| UserPromptSubmit | `auto-continue.mjs` | 只做一件事：把本会话的轮次计数归零（人工介入后重新计） |
| Stop | `auto-continue.mjs` | 读本会话队列：没有队列 → 放行；有 `[ ]` / `[~]` → 递这一条；连续 5 轮没做完 → 标 `[阻塞]`；`[ ]` / `[~]` 都没了 → 请用户确认收尾 |
| Stop | `auto-commit.mjs` | 工作区有未提交改动 → 先跑 `checks.fast`，通过才提醒提交；不通过要求先修 |

**队列标记由 AI 自己写，钩子只读。** 脚本唯一的写操作是"连续 5 轮没做完 → 标 `[阻塞]`"。

代价与收益：把认领交给 AI，"写计划"和"开始干活"就落在同一个回合里；钩子改文件会带来更实际的问题——
AI 刚提交完任务，钩子又改了队列文件，工作区立刻变脏，提交守卫每轮都要为"只改了一个勾"再拦一次。
两边权衡后选了这个：队列文件跟着任务一起进同一个提交，工作区才是干净的。

**放行条件**（`auto-continue` 不拦的情况，按判定顺序）：

1. 不是 Stop 事件；2. 存在刹车文件 `.continue/auto-continue.off`；3. 拿不到会话 ID；
4. 本会话没有队列（纯问答会话不打扰）；5. 队列头部（前 5 行）是 `> 状态：讨论中`；
6. 队列是空的（没有任何条目）；7. 队列里没有 `[ ]` / `[~]`，且**已经请用户确认过收尾**。

**做不完就隔离**：同一条连续 **5 轮**没勾掉 → 标 `[阻塞]`、跳过它继续下一条；收尾时所有 `[阻塞]`
会连同"确认完成"一起摆给用户，不自动丢弃、也不自动重试。用户想重做就改回 `[ ]`。

**收尾（需要用户确认）**：`[ ]` / `[~]` 都没了 → 拦住，让 AI 弹窗给三个选项（确认完成 / 还要补充 /
有做得不对的重做）；确认后才写 `DONE.md` → 更新 `TASKS.md` → 删除队列文件。**只问一次**。

**不会因为"跑太久"中断**：钩子不看上下文长度，只在命中风险五条、或需要你确认收尾时才停。

**想中途停**：`touch .continue/auto-continue.off`（只关自动继续，队列仍在，删掉文件接着跑）；
或删掉本会话的队列文件。提交守卫的刹车是另一份：`.continue/auto-commit.off`。

**日志**：`.continue/logs/<session_id>.md`，只在本机、不进版本控制，超 512KB 转存 `.1`。同目录还有三份
状态：`<sid>.state.json`（轮次/连续计数）、`<sid>.init.state.json`（注入标记）、`<sid>.commit.state.json`
（自测缓存）。**必须分开**——UserPromptSubmit 上两个钩子并行跑，共用一份 JSON 会互相抹字段。

**自测门禁**：`.continue/config.json` 配了 `checks.fast`（本项目 = `npm run check:fast`，实测约 10s），
`auto-commit` 才会在拦人之前**自己跑一遍**：通过 → 正常要求提交；失败 → 改发"先修，不要提交"（附末尾
30 行）；命令不存在/超时 → fail-open。结果按**工作区指纹**缓存，同一份改动只跑一次。

## 4. 本项目约定（迁移自旧队列文档，仍然有效）

**目录分工**（都在 `.continue/` 下）：

| 目录/文件 | 放什么 | 进仓库？ |
| --- | --- | --- |
| `queues/` | 会话级队列 | ✅ 要 review |
| `archive/` | 旧队列与批次流水（只读历史） | ✅ |
| `hooks/` | 四个钩子脚本 | ✅ |
| `TASKS.md` / `DONE.md` / `HANDOFF.md` | 队列规划 / 完成档案 / 本文件 | ✅ |
| `batch-seq` | 批次号自增（`npm run batch:next`） | ✅ |
| `logs/`、`*.off` | 运行日志、状态、刹车 | ❌ 已 gitignore |

**一条 = 一个可独立验证的改动**（能单独 commit）。写清「改哪个文件 / 验收标准」，**不要写"接着上面那个
继续"**——上下文压缩后前面的细节会丢。长跑前先 `git commit` 一次，留个干净起点。

**做完一条的流程**（顺序有意义）：

1. 读队列第一条（长期缺口看仓库根 `TASKS.md` 的 `[~]`，别从头扫）；
2. 定范围：拆成"能一批收掉"的（数据 / 规则 / 一处 UI / 一套断言），拆不动的留回队列并写明为什么；
3. **纯逻辑先行**：`core/...` 里写不引 DOM / 不引世界的模块，每个"如果"都能单独断言；
4. **数据链路四处一起补**：`restoreStack` / `stackExtras` / `sameExtras` / `Transfer.cloneExtras`；
5. 接界面：面板挂 `<body>`、层叠层 12、Esc 自己收、关闭回调交还输入权；**手机横屏是主场景**；
6. 自测 → commit → 勾 `[x]`：`npm run check:fast` 通过、把实测数据写进中文 commit message；
7. 只做一条就停，下一条由钩子下一轮递过来。

**AI 自插任务**：`- [ ] [发现] …`，三条硬条件（真实撞见 + 写证据 / 只插不删改 / 插完明说），
同时最多 5 条——满了钩子会要求先让用户过一遍。额度是防"为了有活干而发明任务"。

**明确不做的事**记在仓库根 `TASKS.md`（`[-]` 标记，`audit:tasks` 会统计），不要在本文件另抄一份。

## 5. 容易踩的地方

1. **队列文件名必须与会话 ID 一致**。改名或手工另存之后钩子读不到、也不报错——表现就是"不继续了"。
2. **格式示例要放进代码块**（三个反引号）。围栏外的 `- [ ]` 会被当成真任务。
3. **一份队列只归一个会话**。两个会话同时改同一份队列，条目状态会错乱（`queue-init` 会提示其他会话的
   未完成队列，但**不会擅自接管**，要先问用户）。
4. **`[~]` 是"进行中"，不是"跳过"**。写成 `[~]` 钩子会一轮一轮递回来，直到连续 5 轮被标 `[阻塞]`。
5. **队列文件要跟任务一起提交**，否则下一轮 Stop 的提交守卫会拦你。
6. **`> 状态：讨论中` 只在前 5 行有效**；写进正文不影响任何东西。
7. **改了 `.codebuddy/settings.json` 不热加载**：钩子在会话启动时拍快照，改完必须重启会话。
   排查"钩子没反应"：`echo '{"hook_event_name":"Stop","session_id":"manual-test"}' | node .continue/hooks/auto-continue.mjs`。
8. **本项目的 `hooks/` 相对框架原版多了刹车开关**（`.continue/auto-continue.off` / `auto-commit.off`，
   迁移时按旧版行为补回）。若以后用 `continue-task` 技能重装覆盖了 `hooks/`，记得把这两段加回去。
