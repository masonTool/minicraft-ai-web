## 3. 队列与标记

每个会话一份：`.continue/queues/<session_id>.md`。文件名必须与会话 ID 一致——钩子只靠 ID 推导路径。

| 标记 | 谁写 | 含义 |
| --- | --- | --- |
| `- [ ]` | AI | 待办（规划时写） |
| `- [~]` | AI | **进行中**（开始做这条时自己改） |
| `- [x]` | AI | 完成 |
| `- [阻塞]` | **钩子** | 卡住：连续 5 轮没做完被隔离，等用户决策 |
| `- [ ] [发现]` | AI | 干活时撞见的新问题，最多 5 条，必须写证据 |

`[~]` 表示"**正在做**"，不是"跳过"；跳过/放弃没有标记，走"回复里说明 + 用户决定"。
早期版本用过 `[-]` 表示进行中，已废弃——同一个意思不留两套符号。

头部三行（**只认文件前 5 行**，正文里提到这几个字不算）：

```md
> 状态：执行中
> 创建：YYYY-MM-DD
> 批次：1351
```

- `> 状态：执行中` —— 钩子开始递任务；`> 状态：讨论中` —— 放行不递任务（还没确认方案时用）；
- `> 批次：<n>` —— `n` = **开工时的提交总数**（`git rev-list --count HEAD`）。建队列时直接照抄
  钩子注入的值（`queue-init` 会算好）。它是这一批的唯一编号：`DONE.md` 标题写
  `## 批次 1351（提交 1351→1354）· 2026-10-22 · 会话 xxxxxxxx`，commit message 也带 `批次 1351`
  ——"这是第几次改动、这批一共动了几次"一眼可见，不必翻 git log。

规则：

1. 讨论阶段不要建队列；要动手时才建，每条都要能独立验证、能单独提交。
2. **一条一条做：做完这一条就停**：开始做时把 `[ ]` 改成 `[~]`，做完改 `[x]` 并单独提交，然后**停下**，
   由下一轮 Stop 钩子把队列里的**下一条**递回来。不要顺手做下一条，更不要在一个回合里把整个队列刷完
   （2026-10-22 用户明确要求：一次刷完，用户就失去逐条检查、逐条叫停的机会）。
   ⚠️ 已知代价（批次 1364 实测）：Stop 钩子只能"请求"续跑，**客户端一个用户消息只肯自动续 1 次**
   （日志 `00:04:47` 钩子递了 T2，客户端没开新回合），所以偶尔需要用户说一句"继续"；
   即使这样也按一条一条走。**例外**：命中"该弹窗问人"的五条、或这条确实做不下去。
3. **收尾要用户确认**：`[ ]` / `[~]` 都没有了 → 先请用户确认；确认后一次性做完这五步：
   ① 整份队列写进 `DONE.md`（含 `[阻塞]`，附完成说明，标题带 `批次 n（提交 n→m）`）；
   ② 整份队列在 `TASKS.md` 里落地（A~O 里已有的条目改 `[x]`；当场才出现的任务补到
   **「队列落地 · 当场任务」** 一节——钩子文案里说的 `C. 已完成` 在本项目叫这个名字，
   `C` 已被「世界存储与区块」占用）；
   ③ **自问一次**：这批有没有"下一批还会被绊到"的设计取舍 → 有就补 `NOTES.md`；
   ④ **自问一次**：这轮有没有会重复踩的坑 → 有就补 `EXPERIENCE.md`；
   ⑤ 删掉队列文件。
   边界：`TASKS.md` 只补 `[x]`，不新增 `[ ]`——未来的计划由用户提；
   `NOTES` / `EXPERIENCE` 只写"确实有"，**不写占位**（占位会让人以为已经读过）。
4. 长期待办只写 `TASKS.md`；本文件只记进度与坑，不记待办。
5. 不停下来等确认；遇到困难自己解决并把结论记下来（收尾确认那一步除外）。
6. `[阻塞]` 只有钩子写，AI 不写也不删；判断某条不该做时在回复里说明理由，交用户决定。

**六份东西各管一件事**（同一内容只写一处，别互相抄）：

| 位置 | 回答的问题 | 组织方式 | 谁写、何时写 |
| --- | --- | --- | --- |
| `TASKS.md` | 接下来做什么（全项目总表，A~O 分段 + 三张派生表） | 按段字母 + 编号 | 用户提；AI 只在收尾补 `[x]` |
| `queues/<sid>.md` | 这个会话这一轮做什么 | 顺序 + 四态标记 | AI，开工前 |
| `DONE.md` | 这批做了什么、怎么验的 | 时间线（批次号倒序） | AI，收尾时 |
| `NOTES.md` | 当时怎么做的、为什么 | 按模块，一节一个决策 | AI，收尾时自问 |
| `EXPERIENCE.md` | 下次怎么避开 | 按主题，症状 → 处置 | AI，踩坑当场或收尾时 |
| `HANDOFF.md` | 机制与当前状态（换人先读这份） | 机制分节 | AI，改机制时 |

判据一句话：**「只有这批需要知道」→ `DONE`；「下一批还会被绊到」→ `NOTES`；
「下次能照着避开」→ `EXPERIENCE`。** 拿不准就写 `DONE`——它是时间线，多写一行不会误导后来人。

## 4. 钩子怎么工作

四个脚本注册在 `.codebuddy/settings.json`（**相对路径**，换机器不用改）：

| 事件 | 脚本 | 做什么 |
| --- | --- | --- |
| UserPromptSubmit | `queue-init.mjs` | 每个会话**第一次**收到消息时，注入会话 ID、队列路径、**批次号**；之后静默 |
| UserPromptSubmit | `auto-continue.mjs` | 只做一件事：把本会话的轮次计数归零（**钩子自己的回灌不算**，见下面日志一节） |
| Stop | `auto-continue.mjs` | 读本会话队列：没有队列 → 放行；有 `[ ]` / `[~]` → 递这一条；连续 5 轮没做完 → 标 `[阻塞]`；`[ ]` / `[~]` 都没了 → 请用户确认收尾 |
| Stop | `auto-commit.mjs` | 工作区有未提交改动 → 先跑 `checks.fast`，通过才提醒提交；不通过要求先修 |

**队列标记由 AI 自己写，钩子只读。** 脚本唯一的写操作是"连续 5 轮没做完 → 标 `[阻塞]`"。

代价与收益：把认领交给 AI，"写计划"和"开始干活"就落在同一个回合里；但钩子改文件会带来更实际的问题——
AI 刚提交完任务，钩子又改了队列文件，工作区立刻变脏，提交守卫每轮都要为"只改了一个勾"再拦一次。
两边权衡后选了后者：队列文件跟着任务一起进同一个提交，工作区才是干净的。

**放行条件**（`auto-continue` 不拦的情况，按判定顺序）：

1. 不是 Stop 事件；2. 存在刹车文件 `.continue/auto-continue.off`；3. 拿不到会话 ID；
4. 本会话没有队列（纯问答会话不打扰）；5. 队列头部（前 5 行）是 `> 状态：讨论中`；
6. 队列是空的（没有任何条目）；7. 队列里没有 `[ ]` / `[~]`，且**已经请用户确认过收尾**。

**做不完就隔离**：同一条连续 **5 轮**没勾掉 → 标 `[阻塞]`、跳过它继续下一条；收尾时所有 `[阻塞]`
会连同"确认完成"一起摆给用户，不自动丢弃、也不自动重试。用户想重做就改回 `[ ]`，重新得到 5 次机会。
隔离只在"连续"上计数：中间换了一条（说明推进了）就归零。

**收尾（需要用户确认）**：`[ ]` / `[~]` 都没了 → 拦住，让 AI 用弹窗（`ask_followup_question` /
`AskUserQuestion`）给三个选项——确认完成 / 还要补充 / 有做得不对的重做；确认后按 §1 规则 3 的五步走。
**只问一次**：问过就放行；一旦重新开始干活，下次收尾会重新问。

**不会因为"跑太久"中断**：钩子不看上下文长度，只在命中风险五条、或需要你确认收尾时才停。
**该停下来问人的五种情况**（命中就弹窗，给 2~4 个具体选项、推荐项放第一位）：

1. **不可逆的破坏**：删数据 / 改存档格式 / 改公开接口 / 强制推送；
2. **会波及其他队列**：要动的文件是另一条的地盘，或改动会让已通过的断言变红；
3. **多种合理做法且取向不同**：性能 vs 一致性、对齐原版 vs 修复体验；
4. **需求本身有歧义**：条目能理解成两个意思，做错了要返工；
5. **超出这条的范围**：做完发现必须顺手改一大片不在本次范围内的东西。

**想中途停**：`touch .continue/auto-continue.off`（只关自动继续，队列仍在，删掉文件接着跑）；
或删掉本会话的队列文件。提交守卫的刹车是另一份：`.continue/auto-commit.off`。

**每个会话只有两个运行时文件**（2026-10-22 收敛，批次 1368）：

```
.continue/logs/<sid>.log         人读的时间线
.continue/logs/<sid>.state.json  机器读的状态（init / continue / commit 三个区）
```

以前是"一个用途一个文件"（`.md` 日志 + 三份 `.state.json`），用户的原话是"我不需要有那么多文件"。
**日志（`.log`）**的四条规则：

1. **只给「有队列的会话」记**：纯问答会话每轮 Stop 也会跑到钩子，但一条日志都不写、
   连文件都不建——以前那里全是 `放行 · 本会话尚未创建队列`，翻日志时还得先认出哪份是干活的。
   要确认"钩子到底有没有被调用"，用下面「钩子没反应时」手动喂事件，别指望这个文件。
2. **时间是本地时区**（`2026-10-22 08:20:44`，文件头写明 `本地时间 +08:00`）。
   以前写 UTC 的 `00:20`，每次对时间都要在脑子里换算。
3. **每行带来源标签**，三个钩子共用一个文件但要分得清谁说的：
   `[init]` = `queue-init`（注入 / 回灌）、`[continue]` = `auto-continue`（递任务 / 放行 / 隔离）、
   `[commit]` = `auto-commit`（提交守卫 / 自测）。
4. **只留关键节点，连续重复的只写一次**：`会话初始化` / `回灌` / `拦截` / `隔离` / `自测失败` /
   `放行`（放行只记异常原因：讨论中、刹车、git 进行中…；"工作区干净"这种每轮都有的不记）。
   单文件不轮转：超 512KB 就地砍掉旧的一半。

**怎么从日志判断"续跑到底成没成"**（最有用的两条，成对出现）：
```
2026-10-22 08:20:44 [continue] 拦截 · Stop 第1轮 · 递任务：「第一条：示例」 · 队列剩 2 条 · 已注入给客户端
2026-10-22 08:20:55 [init] 回灌 · UserPromptSubmit · 第1轮任务反馈已到达客户端（本轮不是用户发言）
2026-10-22 08:20:55 [continue] 拦截 · Stop 第2轮 · 递任务：「第二条：示例」 · 队列剩 1 条 · 已注入给客户端
```
有「拦截」**没有**「回灌」= 钩子递了、客户端没开新回合（批次 1364 实测的"只肯续 1 次"就是这个形状）；
两条都有、且第 N 轮在涨 = 续跑链路正常。**轮次只在用户真的发言时归零**，钩子回灌的那一轮不归零，
否则日志里永远显示"第1轮"，看不出续了几次。

**状态（`.state.json`）**按钩子分区（`init` / `continue` / `commit`），**一份文件三把钥匙**：
UserPromptSubmit 上两个钩子并行跑，写之前用 `mkdir` 锁（`<sid>.state.json.lock`，2 秒视为过期），
避免"读到旧副本再整份写回"把别人的分区抹掉。

**可调开关**（默认值对绝大多数项目合适；要改就在 `.codebuddy/settings.json` 的 `command` 前加环境变量）：

| 变量 | 默认 | 作用 |
| --- | --- | --- |
| `CONTINUE_BLOCK_AFTER` | `5` | 同一条连续几轮没勾掉就标 `[阻塞]` |
| `CONTINUE_DISCOVERED_LIMIT` | `5` | 队列里允许同时存在几条未完成的 `[发现]` |
| `CONTINUE_LOG_MAX` | `524288` | 日志轮转阈值（字节） |
| `QUEUE_INIT_STYLE` | 空 | 设成 `text` 时改用纯文本输出注入内容 |
| `AUTO_COMMIT_STYLE` | 空 | 设成 `json` 时改用 `{"continue":false,"reason":…}` 而不是 exit 2 |

**自测门禁**：`.continue/config.json` 配了 `checks.fast`（本项目 = `npm run check:fast`，实测约 10s），
`auto-commit` 才会在拦人之前**自己跑一遍**：通过 → 正常要求提交；失败 → 改发"先修，不要提交"
（附末尾 30 行）；命令不存在 / 超时 → 不算测试失败，照常要求提交，但要求如实说明"未验证"。
结果按**工作区指纹**缓存，同一份改动只跑一次；要强制重跑就删 `<sid>.commit.state.json`。

**钩子没反应时**：先确认 `.codebuddy/settings.json` 里注册了脚本（改完**必须重启会话**，钩子配置
在会话启动时拍快照，不热加载），再手动喂一条事件看输出：

```bash
echo '{"hook_event_name":"Stop","session_id":"manual-test"}' | node .continue/hooks/auto-continue.mjs
```

有队列时会输出反馈并以 `2` 退出，没有队列时输出 `{"continue":true,...}`。

## 5. 硬性约定（用户要求，必须遵守）

1. **每个独立改动单独提交**：review 变更 → 中文 commit message → `git add` → `git commit` → `git push`，
   全程自动、不等确认；不要攒成一个巨型提交，版本历史要能逐条回溯/回滚。
2. **不停下来等确认**：按 `.continue/queues/<session_id>.md` 队列自己推进；遇到困难自己想办法解决并记录结论，
   而不是把问题抛回给用户。

细节与动机记录在仓库内 `.codebuddy/memory/`（AI 记忆的版本化副本）。

## 6. 命令

```bash
npm run dev                # 开发服务器
npm run check              # 【提交前】typecheck + 单测 + 169 套离线测试 + 三张台账（末尾 check:browser 默认跳过；BROWSER_CHECK=1 才真跑浏览器）
npm run check:fast         # 【改代码时】typecheck + 单测 + 只跑被改动命中的套件（秒级）
npm run shot               # 截图到 .tmp/shots/（没浏览器就跳过）；npm run guard = 控制台零错误门禁
npm run build              # 类型检查 + 生产构建（带 sourcemap，发布用）
npm run build:fast         # 只验"能不能出包"（SOURCEMAP=0，产物 hash 与正式构建一致）
npm test                   # typecheck:tools + vitest + 169 套离线测试
npm run test:offline:changed  # 只跑与本次 git 改动相关的离线套件
npm run audit:tasks        # 任务清单自检（编号重复/跳号 + 本文件进度口径是否过期）
npm run gen:stats          # 地形生成统计（耗时/洞穴占比/矿石产量）
npm run agent:setup        # 跨机器自检
```

`npm run check` 是一条链：`typecheck` + `test`（vitest + **169 套**自建离线测试 + `test:hooks`）
+ 三张台账（`audit:tasks` / `audit:coverage` / `audit:diffs`）+ `audit:docs`；
`test` 的聚合入口是 `tools/run-tests.mjs`（一次 esbuild 打包 + 多进程并行，32s → 9s）。
单套调试仍可直接跑 `npm run test:reach` 这类老命令。

浏览器控制台 `window.__mc`（`src/main.ts` 末尾挂的 App 实例）的完整接口清单 →
[`notes/ops.md`](./notes/ops.md)；`tools/pixel-probe.mjs` 能把"看起来偏暗"
变成可对比的像素亮度数字。

## 7. 跨机器同步的边界

| 随仓库走（git 跟踪） | 只在本机（已 gitignore） |
| --- | --- |
| `.continue/`（队列 / DONE / NOTES + notes / EXPERIENCE / HANDOFF / TASKS / hooks）、`AGENTS.md`、`README.md`、`docs/`、`src/`、`tools/` | `node_modules/`、`dist/`、`.tmp/`（构建与测试产物，含 `*.tsbuildinfo`） |
| `.codebuddy/settings.json`（钩子注册）、`.codebuddy/memory/`（AI 记忆的版本化副本） | `.continue/logs/`（日志 + 计数状态，每轮都变）、`.continue/*.off`（刹车）、`.codebuddy/skills/`（本地技能包）、截图 `shot-*.png` |
| `.codebuddy/memory/`（AI 记忆的版本化副本，`npm run agent:setup` 恢复到本机） | 截图 `shot-*.png`、`.continue/*.off`（刹车开关） |

> 长跑任务列表怎么排、`queues/` 与 `logs/` 为什么分开 → 本文件 §3 / §4。

**唯一的外部依赖：git 远程仓库**（没有远程 = 代码只在本机）。查看 `git remote -v`，
没有就 `git remote add origin <地址>` 再 `git push -u origin main`。

## 9. 本项目约定（流程 / 数据链路 / 界面 / 门禁）

**目录分工**（都在 `.continue/` 下）：

| 目录/文件 | 放什么 | 进仓库？ |
| --- | --- | --- |
| `queues/` | 会话级队列 | ✅ 要 review |
| `hooks/` | 四个钩子脚本 | ✅ |
| `TASKS.md` | 长期待办总表（A~O 分节 + 覆盖度 / 差异台账，脚本核对） | ✅ |
| `DONE.md` | 时间线归档（含批次流水） | ✅ |
| `NOTES.md` + `notes/` | 设计决策（按模块） | ✅ |
| `EXPERIENCE.md` | 踩坑（症状 → 处置） | ✅ |
| `HANDOFF.md` | 本文件 | ✅ |
| `config.json` | 自测门禁命令 | ✅ |
| `logs/`、`*.off` | 运行日志、状态、刹车 | ❌ 已 gitignore |

**一条 = 一个可独立验证的改动**（能单独 commit）。写清「改哪个文件 / 验收标准」，**不要写"接着上面那个
继续"**——上下文压缩后前面的细节会丢。长跑前先 `git commit` 一次，留个干净起点。

**做完一条的流程**（顺序有意义）：

1. 读队列第一条（长期缺口看 `TASKS.md` 的 `[~]`，别从头扫）；
2. 定范围：拆成"能一批收掉"的（数据 / 规则 / 一处 UI / 一套断言），拆不动的留回队列并写明为什么；
3. **纯逻辑先行**：`core/...` 里写不引 DOM / 不引世界的模块，每个"如果"都能单独断言；
4. **数据链路四处一起补**：`restoreStack` / `stackExtras` / `sameExtras` / `Transfer.cloneExtras`；
5. 接界面：面板挂 `<body>`、层叠层 12、Esc 自己收、关闭回调交还输入权；**手机横屏是主场景**；
6. 自测 → commit → 勾 `[x]`：`npm run check:fast` 通过、把实测数据写进中文 commit message；
7. 做完一条**继续做下一条**（见 §3 规则 2 的实测：客户端一个用户消息只肯自动续 1 次）。

**AI 自插任务**：`- [ ] [发现] …`，三条硬条件（真实撞见 + 写证据 / 只插不删改 / 插完明说），
同时最多 5 条——满了钩子会要求先让用户过一遍。额度是防"为了有活干而发明任务"。

**明确不做的事**：状态记在 `TASKS.md`（`[-]` 标记，`audit:tasks` 会统计），
**判定理由**记在 `NOTES.md`（「判定不做」那两节）——免得下次又提一遍却想不起为什么。

**门禁**：单份队列 5000 行（防误粘大文件）、本文件 ≤ 520 行，由 `npm run audit:docs` 检查；
队列收尾时整份进 `DONE.md`，所以它不会像旧版单队列那样一路长到两千行。

**批次号**：用**提交总数**（框架默认），不再维护自增计数器——旧版的 `batch-seq` 与
`npm run batch:next` 已下线（手抄的数字一定会漂，提交数是唯一真值）。

**跨区块地物 / 结构必须"只依赖世界坐标"**（J1/J2/J3 的硬性约定）：

**跨区块地物/结构必须"只依赖世界坐标"**：一棵树的树冠会伸进邻居区块，村庄会横跨好几个区块。
做法是"生成区块 C 时重放 3×3 邻域里各地物的实例，只写入落在 C 的部分"，于是每个地物只属于一个区块。
但这条机制成立的前提是**地物的每个决策都是世界坐标的纯函数**——一旦某处读了本区块的方块数据来做判断，
拥有者与邻居就会得出两种结论，接缝上的树冠只会剩半边。为此：

- `OverworldGenerator.surfaceY(x,z)` 提供"世界坐标 → 地表高度"（4 个粗网格节点求零点再双线性插值）；
- 树干用**强制写入** + 只在拥有者区块里向下补齐（估算高度差 1~3 格时不会悬空）；
- 单列地物（草花蘑菇……）不参与邻域重放，直接用本区块真实地面校准落点；
- 下界的地板高度是解析式，天然满足这条约定。

## 10. 容易踩的地方

1. **队列文件名必须与会话 ID 一致**。改名或手工另存之后，钩子读不到、也不报错——表现就是"不继续了"。
2. **格式示例要放进代码块**（三个反引号）。围栏外的 `- [ ]` 会被当成真任务，队列里凭空多出几条待办。
3. **一份队列只归一个会话**。两个会话同时改同一份队列，条目状态会错乱（`queue-init` 会列出其他会话
   的未完成队列，但**不会擅自接管**，要先问用户）。
4. **`[~]` 是"进行中"，不是"跳过"**。写成 `[~]` 钩子会一轮一轮递回来，直到连续 5 轮被标 `[阻塞]`。
5. **队列文件要跟任务一起提交**，否则下一轮 Stop 的提交守卫会拦你。
6. **`> 状态：讨论中` / `> 批次：` 只在前 5 行有效**。写进正文不影响任何东西。
7. **钩子命令里的 `.continue/hooks/…` 是相对路径**，要求钩子进程的 cwd 是项目根。脚本自身靠
   `import.meta.url` 定位根目录，但 `node` 找不到文件时会直接 `Cannot find module`——这时把注册的
   command 换成绝对路径即可（`npm run agent:setup -- --fix-hooks`）。
8. **刹车开关**（`.continue/auto-continue.off` / `auto-commit.off`）2026-10-22 起已并入
   `continue-task` 技能本身（钩子 + `.gitignore` + 本节的说明），重装不会再丢。
   如果哪天用**旧版**技能包覆盖了 `hooks/`，表现是"刹车文件不起作用"——把这四行加回去即可
   （`lib.mjs` 已导出 `CONTINUE_DIR`，两个钩子各判一次 `existsSync`）。
