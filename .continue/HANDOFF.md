# 接手必读 · 队列机制（.continue/）

> ⚠️ **本文件讲的是"任务怎么跑"**；项目本身的状态与历史在**仓库根** [`HANDOFF.md`](../HANDOFF.md)。
> 分工：根 `HANDOFF.md` = 做到哪了、踩过什么坑；本文件 = 队列怎么排、钩子怎么认、收尾怎么算。

> 队列在 `.continue/queues/<session_id>.md`，长期规划在仓库根 `TASKS.md`，
> 时间线在 [`DONE.md`](./DONE.md)，设计决策在 [`NOTES.md`](./NOTES.md)，
> 动手前避坑看 [`EXPERIENCE.md`](./EXPERIENCE.md)。

## 1. 队列与标记

每个会话一份：`.continue/queues/<session_id>.md`。文件名必须与会话 ID 一致——钩子只靠 ID 推导路径。

| 标记 | 谁写 | 含义 |
| --- | --- | --- |
| `- [ ]` | AI | 待办（规划时写） |
| `- [~]` | AI | **进行中**（开始做这条时自己改） |
| `- [x]` | AI | 完成 |
| `- [阻塞]` | **钩子** | 卡住：连续 5 轮没做完被隔离，等用户决策 |
| `- [ ] [发现]` | AI | 干活时撞见的新问题，最多 5 条，必须写证据 |

`[~]` 表示"**正在做**"，不是"跳过"；跳过/放弃没有标记，走"回复里说明 + 用户决定"。
早期版本用过 `[-]` 表示进行中，已废弃——同一个意思不留两套符号。

头部三行（**只认文件前 5 行**，正文里提到这几个字不算）：

```md
> 状态：执行中
> 创建：YYYY-MM-DD
> 批次：1351
```

- `> 状态：执行中` —— 钩子开始递任务；`> 状态：讨论中` —— 放行不递任务（还没确认方案时用）；
- `> 批次：<n>` —— `n` = **开工时的提交总数**（`git rev-list --count HEAD`）。建队列时直接照抄
  钩子注入的值（`queue-init` 会算好）。它是这一批的唯一编号：`DONE.md` 标题写
  `## 批次 1351（提交 1351→1354）· 2026-10-22 · 会话 xxxxxxxx`，commit message 也带 `批次 1351`
  ——"这是第几次改动、这批一共动了几次"一眼可见，不必翻 git log。

规则：

1. 讨论阶段不要建队列；要动手时才建，每条都要能独立验证、能单独提交。
2. 一次只做一条：开始做时把 `[ ]` 改成 `[~]`，做完改 `[x]`。
3. **收尾要用户确认**：`[ ]` / `[~]` 都没有了 → 先请用户确认；确认后一次性做完这五步：
   ① 整份队列写进 `DONE.md`（含 `[阻塞]`，附完成说明，标题带 `批次 n（提交 n→m）`）；
   ② 整份队列在 `TASKS.md` 里落地（已有条目改 `[x]`，当场任务在 `C. 已完成` 补 `[x]`）；
   ③ **自问一次**：这批有没有"下一批还会被绊到"的设计取舍 → 有就补 `NOTES.md`；
   ④ **自问一次**：这轮有没有会重复踩的坑 → 有就补 `EXPERIENCE.md`；
   ⑤ 删掉队列文件。
   边界：`TASKS.md` 只补 `[x]`，不新增 `[ ]`——未来的计划由用户提；
   `NOTES` / `EXPERIENCE` 只写"确实有"，**不写占位**（占位会让人以为已经读过）。
4. 长期待办只写 `TASKS.md`；本文件只记进度与坑，不记待办。
5. 不停下来等确认；遇到困难自己解决并把结论记下来（收尾确认那一步除外）。
6. `[阻塞]` 只有钩子写，AI 不写也不删；判断某条不该做时在回复里说明理由，交用户决定。

**六份东西各管一件事**（同一内容只写一处，别互相抄）：

| 位置 | 回答的问题 | 组织方式 | 谁写、何时写 |
| --- | --- | --- | --- |
| `TASKS.md` | 接下来做什么 | 优先级（A / B / C） | 用户提；AI 只在收尾补 `[x]` |
| `queues/<sid>.md` | 这个会话这一轮做什么 | 顺序 + 四态标记 | AI，开工前 |
| `DONE.md` | 这批做了什么、怎么验的 | 时间线（批次号倒序） | AI，收尾时 |
| `NOTES.md` | 当时怎么做的、为什么 | 按模块，一节一个决策 | AI，收尾时自问 |
| `EXPERIENCE.md` | 下次怎么避开 | 按主题，症状 → 处置 | AI，踩坑当场或收尾时 |
| `HANDOFF.md` | 机制与当前状态（换人先读这份） | 机制分节 | AI，改机制时 |

判据一句话：**「只有这批需要知道」→ `DONE`；「下一批还会被绊到」→ `NOTES`；
「下次能照着避开」→ `EXPERIENCE`。** 拿不准就写 `DONE`——它是时间线，多写一行不会误导后来人。

> 本项目的落地方式：`NOTES.md` 的索引指向 [`notes/modules.md`](./notes/modules.md)（约 900 行的
> 模块能力台账，2026-10-22 从 `docs/HANDOFF-ARCHIVE.md` 搬来）与 `docs/STATION-LOGIC.md`；
> `EXPERIENCE.md` 里保留着从 `docs/EXPERIENCE.md` 并入的"症状 → 根因"总表。

## 3. 钩子怎么工作

四个脚本注册在 `.codebuddy/settings.json`（**相对路径**，换机器不用改）：

| 事件 | 脚本 | 做什么 |
| --- | --- | --- |
| UserPromptSubmit | `queue-init.mjs` | 每个会话**第一次**收到消息时，注入会话 ID、队列路径、**批次号**；之后静默 |
| UserPromptSubmit | `auto-continue.mjs` | 只做一件事：把本会话的轮次计数归零（人工介入后重新计） |
| Stop | `auto-continue.mjs` | 读本会话队列：没有队列 → 放行；有 `[ ]` / `[~]` → 递这一条；连续 5 轮没做完 → 标 `[阻塞]`；`[ ]` / `[~]` 都没了 → 请用户确认收尾 |
| Stop | `auto-commit.mjs` | 工作区有未提交改动 → 先跑 `checks.fast`，通过才提醒提交；不通过要求先修 |

**队列标记由 AI 自己写，钩子只读。** 脚本唯一的写操作是"连续 5 轮没做完 → 标 `[阻塞]`"。

代价与收益：把认领交给 AI，"写计划"和"开始干活"就落在同一个回合里；但钩子改文件会带来更实际的问题——
AI 刚提交完任务，钩子又改了队列文件，工作区立刻变脏，提交守卫每轮都要为"只改了一个勾"再拦一次。
两边权衡后选了后者：队列文件跟着任务一起进同一个提交，工作区才是干净的。

**放行条件**（`auto-continue` 不拦的情况，按判定顺序）：

1. 不是 Stop 事件；2. 存在刹车文件 `.continue/auto-continue.off`；3. 拿不到会话 ID；
4. 本会话没有队列（纯问答会话不打扰）；5. 队列头部（前 5 行）是 `> 状态：讨论中`；
6. 队列是空的（没有任何条目）；7. 队列里没有 `[ ]` / `[~]`，且**已经请用户确认过收尾**。

**做不完就隔离**：同一条连续 **5 轮**没勾掉 → 标 `[阻塞]`、跳过它继续下一条；收尾时所有 `[阻塞]`
会连同"确认完成"一起摆给用户，不自动丢弃、也不自动重试。用户想重做就改回 `[ ]`，重新得到 5 次机会。
隔离只在"连续"上计数：中间换了一条（说明推进了）就归零。

**收尾（需要用户确认）**：`[ ]` / `[~]` 都没了 → 拦住，让 AI 用弹窗（`ask_followup_question` /
`AskUserQuestion`）给三个选项——确认完成 / 还要补充 / 有做得不对的重做；确认后按 §1 规则 3 的五步走。
**只问一次**：问过就放行；一旦重新开始干活，下次收尾会重新问。

**不会因为"跑太久"中断**：钩子不看上下文长度，只在命中风险五条、或需要你确认收尾时才停。
**该停下来问人的五种情况**（命中就弹窗，给 2~4 个具体选项、推荐项放第一位）：

1. **不可逆的破坏**：删数据 / 改存档格式 / 改公开接口 / 强制推送；
2. **会波及其他队列**：要动的文件是另一条的地盘，或改动会让已通过的断言变红；
3. **多种合理做法且取向不同**：性能 vs 一致性、对齐原版 vs 修复体验；
4. **需求本身有歧义**：条目能理解成两个意思，做错了要返工；
5. **超出这条的范围**：做完发现必须顺手改一大片不在本次范围内的东西。

**想中途停**：`touch .continue/auto-continue.off`（只关自动继续，队列仍在，删掉文件接着跑）；
或删掉本会话的队列文件。提交守卫的刹车是另一份：`.continue/auto-commit.off`。

**日志**：`.continue/logs/<session_id>.md`，只在本机、不进版本控制，超 512KB 轮转成
`.1` / `.2` / `.3`（最旧的被挤掉）。同目录还有三份状态：`<sid>.state.json`（轮次/连续计数）、
`<sid>.init.state.json`（注入标记）、`<sid>.commit.state.json`（自测缓存）。**必须分开**——
UserPromptSubmit 上两个钩子并行跑，共用一份 JSON 会互相抹字段。

**可调开关**（默认值对绝大多数项目合适；要改就在 `.codebuddy/settings.json` 的 `command` 前加环境变量）：

| 变量 | 默认 | 作用 |
| --- | --- | --- |
| `CONTINUE_BLOCK_AFTER` | `5` | 同一条连续几轮没勾掉就标 `[阻塞]` |
| `CONTINUE_DISCOVERED_LIMIT` | `5` | 队列里允许同时存在几条未完成的 `[发现]` |
| `CONTINUE_LOG_MAX` | `524288` | 日志轮转阈值（字节） |
| `QUEUE_INIT_STYLE` | 空 | 设成 `text` 时改用纯文本输出注入内容 |
| `AUTO_COMMIT_STYLE` | 空 | 设成 `json` 时改用 `{"continue":false,"reason":…}` 而不是 exit 2 |

**自测门禁**：`.continue/config.json` 配了 `checks.fast`（本项目 = `npm run check:fast`，实测约 10s），
`auto-commit` 才会在拦人之前**自己跑一遍**：通过 → 正常要求提交；失败 → 改发"先修，不要提交"
（附末尾 30 行）；命令不存在 / 超时 → 不算测试失败，照常要求提交，但要求如实说明"未验证"。
结果按**工作区指纹**缓存，同一份改动只跑一次；要强制重跑就删 `<sid>.commit.state.json`。

**钩子没反应时**：先确认 `.codebuddy/settings.json` 里注册了脚本（改完**必须重启会话**，钩子配置
在会话启动时拍快照，不热加载），再手动喂一条事件看输出：

```bash
echo '{"hook_event_name":"Stop","session_id":"manual-test"}' | node .continue/hooks/auto-continue.mjs
```

有队列时会输出反馈并以 `2` 退出，没有队列时输出 `{"continue":true,...}`。

## 4. 容易踩的地方

1. **队列文件名必须与会话 ID 一致**。改名或手工另存之后，钩子读不到、也不报错——表现就是"不继续了"。
2. **格式示例要放进代码块**（三个反引号）。围栏外的 `- [ ]` 会被当成真任务，队列里凭空多出几条待办。
3. **一份队列只归一个会话**。两个会话同时改同一份队列，条目状态会错乱（`queue-init` 会列出其他会话
   的未完成队列，但**不会擅自接管**，要先问用户）。
4. **`[~]` 是"进行中"，不是"跳过"**。写成 `[~]` 钩子会一轮一轮递回来，直到连续 5 轮被标 `[阻塞]`。
5. **队列文件要跟任务一起提交**，否则下一轮 Stop 的提交守卫会拦你。
6. **`> 状态：讨论中` / `> 批次：` 只在前 5 行有效**。写进正文不影响任何东西。
7. **钩子命令里的 `.continue/hooks/…` 是相对路径**，要求钩子进程的 cwd 是项目根。脚本自身靠
   `import.meta.url` 定位根目录，但 `node` 找不到文件时会直接 `Cannot find module`——这时把注册的
   command 换成绝对路径即可（`npm run agent:setup -- --fix-hooks`）。
8. **本项目在框架原版上补了刹车开关**（`.continue/auto-continue.off` / `auto-commit.off`）。
   若以后用 `continue-task` 技能重装覆盖了 `hooks/`，记得把这两段加回去（否则只剩"删队列"这一种停法）。

## 5. 本项目约定（迁移自旧队列文档，仍然有效）

**目录分工**（都在 `.continue/` 下）：

| 目录/文件 | 放什么 | 进仓库？ |
| --- | --- | --- |
| `queues/` | 会话级队列 | ✅ 要 review |
| `hooks/` | 四个钩子脚本 | ✅ |
| `TASKS.md` | 队列视角的待办 + 判定不做（理由） | ✅ |
| `DONE.md` | 时间线归档（含批次流水） | ✅ |
| `NOTES.md` + `notes/` | 设计决策（按模块） | ✅ |
| `EXPERIENCE.md` | 踩坑（症状 → 处置） | ✅ |
| `HANDOFF.md` | 本文件 | ✅ |
| `config.json` | 自测门禁命令 | ✅ |
| `logs/`、`*.off` | 运行日志、状态、刹车 | ❌ 已 gitignore |

**一条 = 一个可独立验证的改动**（能单独 commit）。写清「改哪个文件 / 验收标准」，**不要写"接着上面那个
继续"**——上下文压缩后前面的细节会丢。长跑前先 `git commit` 一次，留个干净起点。

**做完一条的流程**（顺序有意义）：

1. 读队列第一条（长期缺口看仓库根 `TASKS.md` 的 `[~]`，别从头扫）；
2. 定范围：拆成"能一批收掉"的（数据 / 规则 / 一处 UI / 一套断言），拆不动的留回队列并写明为什么；
3. **纯逻辑先行**：`core/...` 里写不引 DOM / 不引世界的模块，每个"如果"都能单独断言；
4. **数据链路四处一起补**：`restoreStack` / `stackExtras` / `sameExtras` / `Transfer.cloneExtras`；
5. 接界面：面板挂 `<body>`、层叠层 12、Esc 自己收、关闭回调交还输入权；**手机横屏是主场景**；
6. 自测 → commit → 勾 `[x]`：`npm run check:fast` 通过、把实测数据写进中文 commit message；
7. 只做一条就停，下一条由钩子下一轮递过来。

**AI 自插任务**：`- [ ] [发现] …`，三条硬条件（真实撞见 + 写证据 / 只插不删改 / 插完明说），
同时最多 5 条——满了钩子会要求先让用户过一遍。额度是防"为了有活干而发明任务"。

**明确不做的事**：状态记在仓库根 `TASKS.md`（`[-]` 标记，`audit:tasks` 会统计），
**判定理由**记在 `.continue/TASKS.md` 的 §B——两处分工写清，免得下次又提一遍却想不起为什么。

**门禁**：单份队列 5000 行（防误粘大文件）、`HANDOFF.md` ≤ 340 行，由 `npm run audit:docs` 检查；
队列收尾时整份进 `DONE.md`，所以它不会像旧版单队列那样一路长到两千行。

**批次号**：用**提交总数**（框架默认），不再维护自增计数器——旧版的 `batch-seq` 与
`npm run batch:next` 已下线（手抄的数字一定会漂，提交数是唯一真值）。
