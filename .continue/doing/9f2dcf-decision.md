## D26 · 文本输入用"隐藏 input 收字 + canvas 画"，不自己实现键盘/输入法
- 决定：`CanvasTextInput` 在 DOM 里放一个 `opacity: 0` 的 1×1 `<input>`（固定视口内、`pointer-events: none`）承接全部输入与输入法组合态；canvas 只画 `value`、光标、选区、组合态下划线。
- 为什么：中文/日文/韩文要靠系统输入法，而它只认**真实的焦点元素**。自己实现"键盘事件转文字"在桌面英文下能跑，但在输入法下拿不到候选、拿不到组合串，安卓各家的候选栏也不会出现 —— 那是死路。用隐藏 input 之后，`value` / `selectionStart` / `composition*` 事件全是浏览器算好的，这一层只做像素。
- 影响：① 屏幕上多一个 1×1 的隐形节点（必须 `position: fixed` 且**在视口内**，否则 iOS 不弹键盘）；② 焦点归属由调用方决定（点哪块矩形就 `open()` 谁），**同一时刻只能有一个输入框开着**；③ 真机上软键盘会顶起视口，`render` 的矩形要跟着重算（调用方在 resize/visualViewport 变化时自然就会重排）。
