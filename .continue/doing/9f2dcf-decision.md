## D30 · 背包逻辑抽成纯函数，规则由调用方注入；面板自己排版并与 DOM 版并排对照
- 决定：新增 `ui2d/inventoryModel.ts`（`leftClick`/`rightClick`/`quickMove`/`distributeDrag`，只依赖 `SlotAccess` + `Cursor` + 注入的 `MoveRules`）与 `ui2d/InventoryPanel2D.ts`（自己算 36 格布局并绘制）；对照页把 DOM 渲染与 canvas 渲染并排，共用同一份数据与逻辑。
- 为什么：镜像路线能做到"看起来一样"，但做不到"逻辑也搬过来"——用户要的是后者。把规则抽成纯函数有三个直接好处：① 可以用数组跑断言，把 Wiki 上每句话变成一条测试；② 游戏里套一层 `get/set` 就能复用在真实 `Inventory` 上，不需要复制存储；③ DOM 版与 canvas 版以后可以**共用同一份规则**，不会再漂。
- 影响：`ui2d` 多了一层"逻辑模块"（此前只有渲染与读取），但它不 import core —— 堆叠上限与同种判断由调用方注入。⚠️ 目前只覆盖四种操作；**双击收集、右键拖拽逐格放一个、触摸长按分堆**仍在 DOM 版里，下一批补齐后才谈得上"一模一样"。
