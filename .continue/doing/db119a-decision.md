## D1 · 设置项一律"草稿 + 保存"，但游戏模式 / 飞行仍立即生效

- 决定：`SettingsScreen` 里所有 `GameSettings` 字段走草稿，点「保存」才拷回主程序；「游戏模式」下拉与「飞行」开关保持立即生效。
- 为什么：模式与飞行是"这个世界现在的状态"（进存档、改玩法、决定能不能飞），从来不在 `GameSettings` 这份设备偏好里；把它们也做成草稿，就得在"没保存就退回菜单"时回滚世界状态，反而更容易出现半生效的怪状态。用户说的"所有设置项"指的是偏好类设置。
- 影响：切模式/起飞仍然即时；其余设置（视野、灵敏度、按钮大小、外观、音量、语言、昼夜、调试信息）必须点保存。退回旧行为只需把 `draft` 换回 `this.settings`。

## D2 · 代码注释里的"基岩版 / 原版"保留，只清用户能看到的文字

- 决定：UI 文案、六语言表、`docs/store/*.md`、`README.md` 里不再出现"官方 / 非官方 / Mojang / 复刻"等与原版挂钩的表述；源码注释里的"基岩版是这么做的"保留。
- 为什么：注释是工程笔记，写着"为什么这么实现"，删掉等于把依据一起删；用户看到的是界面。要彻底清注释得改上百处，风险远大于收益。
- 影响：仓库内仍能在注释里搜到"基岩版"；界面上（含设置页、商店文案）没有任何官方/原版指向。

## D3 · 导出世界：取消不下载，API 缺失才回退下载

- 决定：有 `showSaveFilePicker` 就弹系统「另存为」，玩家点取消直接结束；只有 API 不存在或写入失败才退回 `<a download>`。
- 为什么：用户要的是"选目录"。取消后偷偷下载一份会让人以为操作失败却又多出个文件；而 Safari / Firefox / Android WebView 没有这个 API，必须有退路。
- 影响：桌面 Chromium 系能选目录；其它浏览器仍是下载目录。`AbortError` 与真实失败分开处理。

## D4 · 设置格式版本升到 5（只为一件事：调试信息默认关）

- 决定：`SETTINGS_VERSION` 4 → 5，v4 及以前的 `showDebug: true` 一律按"旧默认值"迁回关闭。
- 为什么：老存档里那个 `true` 是旧默认值被整份写进去的，分不清"玩家主动开的"和"默认值"；不升版本就只能二选一：要么老用户永远开着，要么把主动开过的人也关掉。
- 影响：老用户第一次升上来调试面板是关的（要开就再点一次）；v5 之后显式打开会正常保留。
