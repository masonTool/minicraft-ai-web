- 任务分层（**仅 >16 条的任务**）：`doing/plan-<会话ID>.md` 与队列**同名配对**（文件名即绑定，不写 `> 计划：`），里程碑 ≥2 阶段；每批做完自动取下一阶段、**完成到里程碑硬停**，最后里程碑没确认不收尾（细则 `notes/plan.md`）· 批次 2338、0022、20261023-0744
- 收尾**归档**（不 `rm`）队列 / 计划 / 决策记录到 `logs/doing-archive/<名>-<会话ID>-<时间戳>.md`；并行任务走 `npm run continue:worktree`（独立树 + 分支推远程，合并由人定）· 批次 0744、20261023-0823

**坑 / 注意**

- 「派生数字不要手抄」与「同一事实写在两处就查两处」是这一段的母题，见 `TIPS.md#工程与基础设施`
- 钩子写完 stdout 立刻 `exit` 会截断长内容（零报错）：一律走 `writeFd`（`fs.writeSync`），见同节 TIPS
- 这套机制的失效几乎都是**静默**的：绑定/反引号各写一份、计划关卡连续 N 轮不推进只放行不升级、**钩子自己崩了宿主也当未阻止**（已由 `run.mjs` 包装器兜住）。改它前先跑 `audit:docs` 的"计划/决策"行
- 文档体量的"行数"会被超长表格绕过（TIPS 曾 499 行 / 190KB）：大表格迁 `notes/`，门禁同时看字节
- `.continue/` 的任务机制（队列 / 钩子 / 门禁）见 `README.md`；`HANDOFF.md` 只留本项目的约定与命令

- 引导卡在 `#hud` 内，必须自带 `z-index` 才点得到（触摸视角面铺满全屏且在 DOM 更晚）；生存路径**只教到石镐**（4 步：木头→工作台→木镐→石镐），删掉的四步 id 由存档"连续前缀"自动兼容（老档直接算完成）· 引导4~6 · 批次 20261022-2220/2330

**坑 / 注意**

- 「设置项写了 ≠ 接线了」且往往只在**一部分设备**上没接线——断言要盯住每一处尺寸都含 `var(--touch-scale`
- 「看得见 ≠ 点得到」：挂在 `#hud` / `#hud-right` 里的可点元素要 `pointer-events: auto` **加** `z-index`，否则点击被全屏触摸视角面吃掉（快捷栏批次 95、引导卡 20261022-2220）。这个坑**只在触摸端暴露**，离线断言查不到，得断言 CSS（见 `TIPS.md#界面与音频`）
- 「图标消失」优先怀疑**缓存毒化**而不是绘制失败：图集 `deferPaint` 阶段拼出来的等轴图标全透明，还会被按 blockId 缓存住（只认 `revision`）——一旦在铺像素之前画过一次，这个方块在本页所有界面都永久空白（见 `TIPS.md#界面与音频`）

## 维护规则

1. **只有已完成的才进模块图**；待办只在 `TASKS.md`，规划只在队列。
2. 一个需求跨多批完成时，**按批次分行累加**，不要覆写成"批次 A→B"（会丢掉中间过程）。
3. 一个实现只挂**一个**模块（改动最多的那个）；横跨多个模块就在别的模块补一行"见 §X"。
4. 坑只写**一行摘要**，细节留在 `TIPS.md`，不在两处各写一遍。
5. 模块名必须与 `TIPS.md` 的分节标题一致——它就是两者之间的链接键。
6. 只写结论，不贴代码、不写验证过程（那些在 `DONE.md` 的条目说明里）。
