# 实现总览 · OVERVIEW

> 按**模块**回答三件事：这个模块现在有什么、对应台账哪一段（需求号 `A1`~`O16`）、哪个批次做的；
> 外加这个模块**有哪些坑要注意**。
>
> 它是**单一入口**：动某个模块之前先看这里 → 要看那批的具体过程点 `DONE.md` 的批次小节 →
> 要看某个坑的细节点 `TIPS.md` 的同名模块。
>
> 谁写、何时写：AI，**队列收尾时**。同一件事只在这里挂一行，不把 `DONE` / `TIPS` 的正文抄过来。
> ⚠️ 本项目的需求号是 `A1`~`O16`（不是框架默认的 `T<n>`），`TASKS.md` 按段字母分节。

## 一、模块详情

### 工程与基础设施

**实现**

- TypeScript 严格模式 + Vite + Three.js / WebGL2；无第三方运行时依赖（除 `three`）· `A1`~`A5` · 批次 1~9
- 离线测试 169 套（`tools/run-tests.mjs` 并行跑）+ vitest 单测，`npm run check` 是一道门 · `A6` · 批次 589
- 浏览器侧四块命令（截图 / 控制台零错误 / 像素差 / 起服检查），`BROWSER_CHECK=1` 才真跑 · `A7` · 批次 1357

**坑 / 注意**

- 「派生数字不要手抄」与「同一事实写在两处就查两处」是这一段的母题，见 `TIPS.md#工程与基础设施`
- `.continue/` 的任务机制（队列 / 钩子 / 门禁）见 `README.md`；`HANDOFF.md` 只留本项目的约定与命令

**实现**

## 维护规则

1. **只有已完成的才进模块图**；待办只在 `TASKS.md`，规划只在队列。
2. 一个需求跨多批完成时，**按批次分行累加**，不要覆写成"批次 A→B"（会丢掉中间过程）。
3. 一个实现只挂**一个**模块（改动最多的那个）；横跨多个模块就在别的模块补一行"见 §X"。
4. 坑只写**一行摘要**，细节留在 `TIPS.md`，不在两处各写一遍。
5. 模块名必须与 `TIPS.md` 的分节标题一致——它就是两者之间的链接键。
6. 只写结论，不贴代码、不写验证过程（那些在 `DONE.md` 的条目说明里）。
