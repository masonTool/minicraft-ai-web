## 工程与基础设施

### 队列条目写成 `[T1]` 会被门禁当成需求号，提交直接被拒

- 症状：新建队列用 `- [ ] [T1] …` 编号，`git commit` 被 continue-do 的 `ids` 检查拒掉：
  「引用了 T1…，但 TASKS.md 里没有这些需求」，整套 `--fast` 白跑 15 秒。
- 根因：`audit-ids.mjs` 用 `/\bT(\d+)\b/g` 扫**队列条目行**，把 `[T1]` 当成跨文件需求引用；
  而本项目的需求号是 `A1`~`O16`，`T<n>` 只是框架模板里的占位写法。
- 处置：队列条目用中文前缀（`[引导1]` / `[创造2]` / `[小游戏3]`）或任何非 `T+数字` 形式；
  已经写成 `[Tn]` 就改前缀重提，**不要**用 `--no-verify` 绕。
- 适用面：每次新建队列都会撞上，属机制性坑，不是一次性错误。

### 用 shell 双引号包多行文档改文件，反引号会被求值掉

- 症状：`node -e "..."` 里写带反引号的 Markdown，跑完提示一串 `command not found: NOTES.md`
  （zsh 还会说"没有那个文件"），而**文件已经被写坏了**——反引号里的内容被当成命令执行、替换成空串，
  几百字只剩骨架，退出码还是 0。
- 根因：双引号里 `$` / 反引号 / `\` 仍会被 shell 展开（命令替换先于 node 执行）；单引号能挡，
  但单引号包不住正文里的单引号。
- 处置：改文档一律走编辑工具；确实要脚本拼接就把正文先写成临时文件（`.tmp/xxx.md`），
  脚本里只 `readFileSync` 取来拼接——**全文交给工具，shell 只传路径**。已经写坏就
  `git checkout -- <file>` 回滚重来（比手改污染体快得多）。
- 适用面：本仓库文档大量含反引号（路径 / 命令 / 字段名），凡"把多行文本塞进 shell 参数"的场合都会中招。

### 重装 continue-do 会覆盖 `hooks/`，本项目改过的口径会被悄悄改回去

- 症状：重装框架之后**每次 `git commit` 都被拒**，报 `TASKS.md N 行 > 上限 600`；或队列目录又变成
  `queues/`、踩坑文档又说 `EXPERIENCE.md`。功能一行都没改，门禁却全红。
- 根因：安装器对 `.continue/hooks/*.mjs` 与 `.continue/.gitignore` 是**总是覆盖**（不覆盖等于升级失效）；
  `config.json` 只补缺失的键（所以 `checks.*` 会保留）；业务文档内容不同时只**另存** `*.continue-do.md`。
  所以"在 `lib.mjs` 里放宽 `DOC_LIMITS`"这类局部改动必然被抹掉，而且报错不会告诉你是本项目改过的。
- 处置：① 装完立刻跑 `npm run check`；② 本项目把放宽项记在 `tools/audit-docs.mjs` 的
  `PROJECT_DOC_LIMITS`（`TASKS=7000`），被改回去时它当场报出"应为 N"；③ 装完把 `*.continue-do.md`
  备份并进正本后**删掉**——两份指令并存时 AI 会读到冲突的两套规则；④ 钩子配置在会话启动时拍快照，
  改完要**重启会话**。
- 适用面：任何一次 `.codebuddy/skills/continue-task` 的重装 / 升级。

### 本仓库复制一份"框架行为断言"，迟早与框架脱节

- 症状：`npm test` 里 `test:hooks` 整片红，而钩子其实工作正常——断言在找旧文案（"三个收尾选项"、
  `NOTES`+`EXPERIENCE`、`queues/<sid>.md`）。
- 根因：`tools/hooks-test.mjs` 是照抄框架行为写的（581 行）；框架一升级，它守的契约就没了。
  这与"文案字面量断言"是同一类病：**守着别人的实现细节**。
- 处置：框架自己带 `selftest.mjs`（在临时副本里灌事件，覆盖递任务 / 注入 / 提交守卫 / pre-commit），
  本仓库只保留一行委派：`"test:hooks": "node .continue/hooks/check.mjs hooks"`。**键名留着**，
  这样 `run-tests.mjs` / `audit-tasks.mjs` 的 `NON_SUITE_KEYS` 名单不用动。
- 适用面：任何"给第三方框架写自测"的场景——要么委派给它的自检，要么只测**你自己那层**的胶水。

### 钩子日志会被清掉，所以"断点"不能只记在 logs/ 里

- 症状：问"这套自动续跑的机制为什么停了"时，`.continue/logs/<sid>.md` 只剩一行 `Init`，
  几小时前还读到的 20 多条 `Stop · 递任务` 全没了（目录里也没有 `.1`/`.2` 轮转文件，
  说明不是 512KB 轮转，而是文件被整个移除后重建）。于是"到底停在哪一条"没法自证。
- 根因：`logs/` 被 `.continue/.gitignore` 排除，只在**本机**；`appendLog` 只追加、从不清空，
  所以清空一定来自外部（清理脚本 / 手工 / 目录被删后重建）。这类运行时目录天生不可追溯。
- 处置：排查"为什么停了"时，**别把 logs/ 当唯一证据**——它能被删。可靠的做法是让证据跟队列一起进仓库：
  ① 看队列文件的 `[ ]`/`[~]` 状态（AI 每轮改、随任务提交）；
  ② 看 `git log` 里最后一个带 `批次 <号>` 的提交（做到哪一步一目了然）；
  ③ 需要更细的，再翻 `DONE.md` 的归档（整份队列原文照搬，含 `[阻塞]`）。
- 适用面：任何"只写在本机 gitignore 目录里的运行日志"——它是一个便利设施，不是审计日志。

### 用行数给文档设预算，会被"超长表格"绕过

- 症状：`TIPS.md` 499 行 / 190KB，行数门禁显示 499/500"快满但还能过"；按 token 算它是 `README.md` 的六倍，整份读会直接吃掉大半上下文。
- 根因：行数只度量"条目数"，不度量"单行长度"。一张 379 行的两列表，每行几百字，行数看着正常、字节已经爆炸。
- 处置：文档预算同时设"行数 + 字节"（`DOC_BYTE_LIMITS`）；大表格 / 历史清单整段迁 `notes/`，主文件只留指针；`audit-docs` 两条都查。
- 适用面：任何"用行数限制上下文成本"的门禁，尤其是 Markdown 表格、长列表、自动生成台账。

### IDE 终端里的删除会被 safe-delete 垫片"删一半"，并发跑同一套测试还会互相清场

- 症状 A：e2e 的 `milestone`/`journey`/`worktree` 报 `[safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED] {"count":500,"threshold":500,...,"targetCount":1}`——报错指向的只是删一个 `run.md`。
  症状 B：某个场景目录只剩几个文件、断言全红（`main` "钩子一次都没跑起来"），可脚本里没人删过它。
- 根因：IDE 终端用 `NODE_OPTIONS --require` 注入 safe-delete 垫片，`fs.rmSync` 和 `PATH` 里的 `rm` **都**被接管：
  按 `toolCallId` 累计删除条数（阈值 500），超了就**删到一半停下**并把文件挪进系统废纸篓（不是真删）。
  整个 e2e 跑在**一个 tool call** 里，"清上一轮"一次就能贡献 499 条；两轮 `--all` 并发时，后一轮的"先清场"直接删掉前一轮正在用的目录。
- 处置：脚本自己删东西一律用**绝对路径** `/bin/rm`（不过 shell 函数、不过 PATH 垫片）；删完校验"真的没了"，删不掉就停；
  跨轮次的资源（现场目录 / 锁）加 `.e2e/.lock`，且**锁要早于清场**。事故记录见 `DONE.md` 批次 20261023-1603。
- 适用面：任何在 IDE 终端里清目录的脚本（不只 e2e），尤其"删完就当成功"（不看退出码）的写法——半删的现场比不删更误导人。

### 扫源码找"这段文案有没有被用到"，别用成对引号切字面量

- 症状：`npm run audit:i18n` 报"73 条文案没被引用"，实际只有 4 条是真的。典型误报：
  `inventory.recipeBook` 明写在 `InventoryScreen.ts:1038`；`settings.opt.fps30/fps60` 由
  `t(\`settings.opt.fps${n}\`)` 拼出来；`settings.group.*` 由 `t(\`settings.group.${g}\`)` 拼出来。
- 根因：判据是"成对单引号之间算一个字符串"。一行里反引号模板与单引号混排时**配对会错位**，
  后面整段都被切乱；模板拼键更是完全看不到（键在运行时才诞生）。
- 处置：① 引用判据改**子串包含**（`code.includes(key)`），不解析引号；② 另收一遍
  `` t(`前缀${…}`) `` 的前缀，`key.startsWith(prefix)` 算引用，前缀短于 4 字符不收
  （`settings.` 会把整片键洗白）；③ 把前缀打进报告，过宽前缀一眼可见。修完 73 → 0。
- 适用面：任何"扫源码统计字符串使用"的脚本（覆盖率、死代码检测、文案去重）。

### 两个 `romanLevel` 同名不同口径：`StatusEffects` 吃 amplifier（0→I），`enchantments` 是 1 起始

- 症状：「力量药水 II」被印成「力量药水 I」、「缓慢药水 IV」印成「III」—— 差整整一级，而**不报错**。
- 原因：`itemNames.ts` 里用的是 `enchantments.romanLevel`（1 起始），药水的 `amplifier` 是 0 起始；
  `potions.ts` 用的是 `survival/StatusEffects.romanLevel`（直接吃 amplifier）。两处注释都警告过，
  但键化药水名时照样抄混了一次（批次 20261024-0020，靠"改造前后逐字 diff"才发现）。
- 判据：**跨模块搬数字前先看它旁边那个 `romanLevel` 是从哪个文件 import 的**；
  更省事的办法是照抄项目里已有的做法 —— `itemNames.ts` 里所有 `+ 1` 都是在补这个差。
- 兜底：这类"名字由数字拼出来"的改造，跑一次"改造前后全量逐字 diff"（105 瓶 + 35 支箭 diff 为 0 才算过）。

### 往"已闭合"的锚点后插代码：别把锚点自带的 `}` 和收尾语句一起抄进新增块

- 症状：`tools/i18n-test.ts` 报 `TS1128: Declaration or statement expected`（多一个 `}`），
  删掉多余行又变成 `TS1005: '}' expected`（少一个）—— 来回两次都没对。
- 原因：锚点选的是"某段循环的最后两条语句（`check(...)` + `}` + `resetLanguageForTest()`）"，
  而我把它**整段**当锚点，又在新增内容里重复写了一遍 `}` 与 `reset` —— 于是每插一次就多一组闭合。
  修的时候按"看起来多余的 `}`"删，又删到了外层的真闭合。
- 判据：用带闭合符号的行做锚点时，**新增块的结尾只写自己那份**；不确定就先 `git checkout -- <file>`
  回滚重来，别在破括号的文件上继续删（越删越乱）。
- 更稳的写法：把新增断言包进**独立 `{ }` 块**（`{ const ids = ...; check(...); }`），
  这样它与锚点所在作用域解耦，插错也只影响自己那一块。
- 适用面：所有"往长测试文件里追加断言"的编辑（`tools/*-test.ts` 尤其多）。

### 找"漏翻的文案"要按**出口**反查，不是按文件排名扫

- 教训：按"每文件含中文行数"排序，前几名全是 `advancements.ts` / `itemNames.ts`（回退原文，不用翻），
  于是 `CHARACTER_PRESETS[].label`（外观预设 4 条）、`WORLD_TYPE_HINTS`（世界类型说明 5 条）、
  `main.ts` 的 25 处 `hudToast.show('…')` 全被漏掉了 —— 它们分散在长尾文件里，行数只有几条。
- 正确判据：**从 UI 出口往回找**。grep 这些形态：
  `textContent =` / `.setAttribute('aria-label'` / `\.show\(` / `\.info\(` / `\.error\(` /
  `label:` / `placeholder:` / `title:`，再筛"字符串里含中日韩字符"的行。
- 补一步交叉验证：命中的字段（如 `preset.label`、`WORLD_TYPE_HINTS[type]`）要**拿到使用点**确认它真的
  进了 DOM —— 我上一轮就是因为 grep 只搜了 `preset.label` 而漏了 `button.textContent = preset.label`。
- 适用面：任何"文案散在数据表 + 组件"的项目；尤其注意**同一概念有两张表**的情况
  （`worldTypeLabel()` 已 i18n，但 `WORLD_TYPE_HINTS` 是另一张，且只有后者显示在界面上）。

### `git add -A` 会把技能包 / 工具落盘的资产一起提交

- 症状：一次 `git add -A` 之后，提交里多了 26 个 `.codebuddy/skills/…` 文件（`SKILL.md`、`assets/.continue/*`），
  它们不是项目代码，是技能安装时落盘的模板。
- 处置：`git rm -r --cached .codebuddy`（**只移出跟踪，工作区文件不动**）+ `.gitignore` 加 `.codebuddy/`。
  注意 `.gitignore` 里可能已有 `.codebuddy/hooks/logs/` 这种**子路径**规则，别被"已有 .codebuddy 字样"骗过去 ——
  整目录规则要单独一行 `.codebuddy/`。
- 判据：提交前 `git status --short` 扫一眼，出现非 `src` / `tools` / `.continue` / `docs` 的路径就先问一句"这是谁写的"。

### 给语言表追加键：**中文表与非中文表的结尾格式不同**，别写死一种

- 症状：脚本按 `} as const;` 找插入点，中文那份顺利，另外五份直接 `AssertionError`
  （它们的结尾是 `} satisfies Pick<Messages, keyof typeof zhXxx>;`）。
- 更隐蔽的一层：原文件的**最后一条键后面没有逗号**，追加前必须补一个，否则 `TS1005: ',' expected`。
  我第一次给 `misc.ts` 追加就漏了逗号，六个文件里坏了一个。
- 稳妥写法：
  1. 先 `rstrip()`，断言最后一行以 `}` 开头（不管是 `as const` 还是 `satisfies`）；
  2. 从倒数第二行往上找第一个**非空行**，没有逗号就补；
  3. 在最后一行之前插入新键；
  4. 用 `re.sub` 先删掉同名键（重复追加时幂等）。
- 判据：写完立刻 `npm run typecheck` —— 漏逗号/漏大括号都会在这里炸，不必等 `test:i18n`。

### 局部变量 `const t = …` 会遮蔽 i18n 的 `t`，编译器能抓，但报错信息不直说

- 症状：加了 `t('cmd.reply.emptyValue')`，`TS2721: Cannot invoke an object which is possibly 'null'`
  —— 看着像"t 可能是 null"，实际是**这个作用域里的 `t` 被别的东西占了**。
- 成因：`/time` 命令那段有 `const t = parseTime(args[1])`（`t` 是 time 的缩写），
  同一函数里再写 `t('key')` 就是在调用 `parseTime` 的返回值。
- 处置：优先用同文件里已有的**本地辅助**（本项目命令层有 `msg('key', params)` 这个简写），
  它的语义就是"取一条文案"，不必碰全局 `t`；否则给 i18n 的 `t` 起别名（`import { t as tr }`）。
- 判据：`grep -n "const t = \|let t = "` 在改文件前先跑一遍 —— 命令解析、时间、温度这类
  领域里 `t`/`s`/`v` 极常见。改文案是"加一行"，很容易撞上。
- 适用面：所有把 `t()` 当全局可用的项目（尤其命令/解析器这类短变量密集的模块）。

### 说明模板的参数用「整件物品名」，不要用颜色词 / 材质词去拼

- 场景：16 色 × 5 形状 = 80 个方块的说明，句式完全相同，只差颜色。
- **错的做法**：模板写 `{color}羊毛：…`、`{color}混凝土：…`。中文成立（"白色羊毛"），但
  俄语 `Белый`（阳性）配 `шерсть`（阴性）就错，法语 `blanc` 还要注意位置，德语要连写成 `Weißwolle`。
  每个形状都得为每个语言单独排一遍 —— 5 形状 × 6 语言 = 30 条模板，且极易漏。
- **对的做法**：模板参数直接传**整件物品名** —— `tp('item.desc.tpl.wool', { name: tp('item.tpl.wool', { color }) })`。
  物品名那一层**已经**由各自的物品名模板解决了性数/连写问题（`Weißwolle` / `Шерсть (Белый)` / `Laine (blanc)` / `Lã (branco)`），
  说明模板只管后面那句"怎么用"，5 条模板覆盖 80 个方块。
- 判据：凡是要拼文案的族，先问一句「**这个位置有没有现成的整件名字可以复用**」。
  颜色族、台阶墙（`{base}` + 形状）、木质形状（`{name}` = 橡木栅栏）都是这个套路。
- 反例备忘：基座名有两种来源（**显式键** `item.cobblestone` vs **模板拼的** `item.tpl.woodPlanks`），
  用错会得到 `item.oak_planks楼梯` 这种把键名印到界面的结果 —— 拼之前先 `t()` 一次看是不是键名。

### 断言按**文本**匹配 JSON 片段：任何一次格式化重排都会把它打破

- 症状：只是把 `manifest.webmanifest` 的 `name` 改个名（用 `json.dumps(indent=2)` 写回），
  `ui` 套件立刻报「manifest 以横屏全屏打开」失败 —— 内容一个字段没动。
- 原因：那条断言查的是 `manifest.includes('"display_override": ["fullscreen", "standalone"]')`，
  而重排把数组展开成了多行，**文本不再匹配**。JSON 语义完全没变。
- 两种修法，选哪个看责任在谁：
  1. **本次改动**破坏了既有格式 → 把文件恢复成原格式（本项目选了这个：只把那一段写回紧凑一行，
     `gen-manifests` 派生的另外五份仍展开，但断言只查基准文件）；
  2. **判据本身太脆** → 改成 `JSON.parse` 后比值；但要意识到这会放宽"格式意图"的检查
     （别人可能就是想让某个字段保持紧凑写法）。
- 判据：改 JSON/JSON5/TOML 文件时，**先看有没有断言在按文本匹配它**（`grep 'includes('`），
  能"定点改值"就别整文件重写。
- 适用面：`manifest*.webmanifest`、`package.json`、`tsconfig.json`、`config.json`。

### 「语言表 100% 齐」不等于「界面没有中文」—— 要扫的是渲染输出

- 症状：`audit:i18n` 报每张表 2168/2168、`satisfies` 过、`test:i18n` 全绿、四语言巡查 20 条也全绿，
  但用户一眼看到「新建世界的难度还是中文」「药水名还是中文」。
- 两种成因（都**不在语言表里**）：
  1. **根本没查表**：`DIFFICULTY_LABELS` / `GAME_MODE_LABELS` / `GL_FAIL_TEXT` 这类中文常量直接给界面用；
     `item_frame` / `painting` 是 `put('item_frame', '物品展示框')` 一行常量绕过了表。
  2. **查了表但取的是旧值**：`DESCRIPTIONS[key]` 存字符串（模块加载时求值），
     `potions.ts` 的 `name: '迅捷药水'` 是构建时拼好的整句。
- 判据（可复现）：按**渲染输出**扫，不按表扫 ——
  `translateName(所有物品 id)` 与 `itemDescription(id)` × 四种语言，任何中日韩字符即失败
  （`test:i18n` 的「输出侧守卫」就是这么写的，1130 × 4 × 2 = 9040 次）。
- 顺带记住：这类问题的**触发点常是"用户说某处没翻"**，而语言表怎么查都是满的 ——
  先跑一遍输出扫描定位，别急着翻表。
- 适用面：任何"数据驱动文案"的项目（`translateName` / `label(...)` / `description(...)` 这类取值函数）。

### 说明类文案存"字符串"还是"函数"：存字符串 = 只在加载那一刻的语言下正确

- 症状：把 `DESCRIPTIONS[key]` 里的中文挪进语言表之后，切到德语界面**说明仍然是中文**；
  而语言表 100% 覆盖、`audit:i18n` 也不报、`satisfies` 也过。
- 原因：`DESCRIPTIONS[key] = \`...\${t(...)}...\`` 是**模块加载时求值**的字符串 —— 记下来的是
  "那一刻的语言"（默认中文）。工具 / 盔甲 / 珊瑚 / 药水那几族一开始就写成 `() => tp(...)`，
  所以从没暴露；食物那 13 条（苹果、牛肉、腐肉、金苹果…）原来拼的是纯中文常量，
  "反正只有中文"看着没问题，一搬进表就露馅（批次 20261023-2217 实测）。
- 判据：凡是"由 `t()` / `tp()` 参与拼装、又要随语言变"的值，**必须存函数**，由渲染处调用
  （`itemDescription()` 已经是 `typeof value === 'function' ? value() : value`）。
- 自查一行：`grep -n "DESCRIPTIONS\[" src/core/registry/itemNames.ts`，看赋值右侧是不是 `() =>`；
  另有 `useState`-式的延迟表（`ADVANCEMENT_TEXT`、标签表）同理。
- 为什么容易漏：**静态表条目会遮住动态表**。同族 36 条里 23 条有 `item.desc.<id>` 静态条目、
  13 条没有 —— 只翻静态条目的那部分，问题看起来"已经没了"。

### 分批切语言表：切完必须"按组核对"，一个组整组等于英文 = 整组漏了

- 症状：法语表"键集 100% 齐、`satisfies` 过、`test:i18n` 全绿"，但界面上 226 条标签
  （效果 / 群系 / 附魔 / 职业 / 外观）全是英文。没有任何检查会报 —— 占位值本来就能通过一切"键集"检查。
- 根因：分批时按"界面层 / 背包 / 物品 / 命令 / 说明"切，**某一组掉在两批之间没人认领**。
  德语、俄语的 `label` 都在各自第二批，法语重写清单时切法变了，就漏了。
- 判据（一行）：按组统计 `table[key] === enTable[key]` 的条数，**某组 90% 以上相等就是整组漏翻**。
  已固化成 `test:i18n` 的"巡查 <lang>：没有整组仍是英文的组"。
- 适用面：任何"分批搬迁/翻译一张大表"的活；也别只信"覆盖率 100%"那一栏。

### 加语言 / 改文件名时，这些断言一定要跟着挪（否则红得莫名其妙）

- 三类会同时炸，且报错信息都指不到真正原因：
  1. **"没做表的语言"的例子**：`ru` → `pt` → …每加一种真实语言就往后挪一格；六种都有表之后
     只能造一个码（`'xx' as LocaleCode`），并断言**它不会漏进语言选择器**（清单只认 `LOCALES`）。
  2. **"支持 N 种语言"的计数**：`availableLanguages().length < LOCALES.length` 这类"还有语言不能选"
     的断言，在最后一种语言上表时必然红 —— 改成"六种都能选"。
  3. **源码里硬编码的文件名**：`boot()` 换 manifest 时按语言拼文件名了，断言却还在检查
     `'./manifest.en.webmanifest'` 这个字面量 → 改成检查 `manifest.${uiLang}.webmanifest` 的拼法。
- 适用面：语言清单、"可选/不可选"、静态资源按语言分支这三处。

### 多语言断言别写"译文必须不同于原文"——语言中性的条目会被误判

- 症状：`test:i18n` 报"这三条回执没翻成英文"，实际它们本来就该一模一样（`{name} Health = {value}` 这类只由占位符与专有名词组成的句子）。
- 根因：判据写成了 `t(key,'zh') !== t(key,'en')`。中文里没有汉字可翻的句子，
  英文值就是同一串；用"必须不同"当漏翻判据，等于假设每条文案都含可翻译的自然语言。
- 处置：判据改成**"中文里含汉字时，英文才必须不同"**——`/[\u4e00-\u9fff]/.test(t(key,'zh')) && t(key,'en') === t(key,'zh')`
  才算漏翻。同一处坑在 P0-6（判英文表完整性）和 P1-6（判回执是否翻译）各踩了一次。
- 适用面：任何"译文完整性/覆盖率"断言；P2 的物品名与生物名里会有更多语言中性条目（`TNT`、`Elytra`）。

### 把常量表搬进语言表时，`key in TABLE` / `TABLE.size` 这类"直接读表"的判断必须一起改

- 症状：文案明明一条没动（全量 diff 为零），但十几套测试一起红，报"没有中文名 / 没有说明"。
- 根因：判断"有没有这条文案"的地方不是走查表，而是直接读常量表：
  `hasDescription()` 的 `key in DESCRIPTIONS`、`knownNameCount()` 的 `NAMES.size`、
  `missingBlockNames()` 的 `NAMES.has(key)`。表搬走后这些判断全部变成 false，
  于是"文案还在、只是换了地方"被读成"文案没了"。
- 处置：抽一个 `hasXxx(key)` 判据，**两处都查**（语言表 + 还没搬走的旧表），
  判断统一走它。搬完最后一批再把旧表那半删掉。
- 适用面：任何"表正在被分批搬迁"的迁移（i18n 文案、注册表、标签表）。
  同一处坑在 P2-2（物品名）与 P2-3（物品说明）各踩一次，第二次仍漏了 `hasDescription` ——
  所以搬迁时**先 grep 一遍所有读表的地方**（`in TABLE`、`.size`、`.has(`），别等测试红。

### 加一种语言时，复数表最容易漏 —— 而且漏了不会报错

- 症状：德语界面上出现「1 Blöcke」（应为「1 Block」）。`tn()` 找不到该语言的复数表时会**回落到 `t(key)`**，
  于是一条写死的复数形式就这么印出来了，测试全绿。
- 根因：`PLURAL_TABLES` 里只登记了 `en`。德语的 one/other 恰好被英文的 `t()` 兜住，**一直没人发现**，
  直到俄语开始写复数表（4 类：one/few/many/other）才暴露。
- 处置：`locales/<code>/plural.ts` 与语言表**成对存在**，登记进 `PLURAL_TABLES`（静态导入 —— `tn()` 必须同步拿到它，
  而它只有几行）；断言盯**具体数字**而不是"有没有表"：
  `1 блок | 2 блока | 5 блоков | 21 блок`、`1 Block | 2 Blöcke`、`0 blocks | 1 block | 5 blocks`。
- 适用面：任何带数量词的文案（`{count} 格`、`可烧 N 次`、`还剩 N 次酿造`）。

### 模板拼名时，先问"这门语言的形容词要不要变格"——要变，就别用平坦模板

- 德语能拼：`Diamantspitzhacke`、`Weißwolle`（复合词永远不算错），所以 `{material}{kind}` 直接成立。
- 俄语不能拼：`алмазная кирка` / `алмазный топор` —— 形容词要随名词的性、数变。平坦模板必然错一半。
  同样的坑还有颜色 16 色 × 10 族（`Шерсть (Белый)`）。
- 处置：**能自然拼的走模板**（木材词干 `Дубов` + `ое/ые/ый`、珊瑚 `Трубчатый коралловый блок`），
  **拼不了的走"括号归属式"**（`Кирка (алмаз)` / `Плита (Камень)` / `Шерсть (Белый)`），语法正确 > 风格统一。
- 判据：如果一个"词"在目标语言里会因为后面的名词改变拼写，它就不是构件，而是句子的一部分。

### 聊天栏 / 提示条是唯一"字符串进来就显示"的出口，类型系统看不见漏翻

- `chat.push(text)` / `hudToast.show(text)` 的入参**直接落 DOM**，`string` 里塞中文永远合法，`satisfies` 与 `audit:i18n` 都只看"键有没有"。处置：句子进 `say.*`；`i18n-test` 守卫——剥注释后扫源码，这两个调用的**第一个实参是字面量且含汉字**就红。**静态 CSS** 同病（`content: '展开'` 切语言不重绘）→ `content: attr(data-xxx)` 由 JS 写属性。

### 「协议里有这个字段」不等于「它生效了」 / `net` 套件并发假红

- 根因同一类：① 队友看不到你的甲/副手/蹲姿，而 `move.armor`/`offhand`/`sneak` 早进白名单并被转发——**发送端没填**或**消费端没用**；② `net` 并发偶发红、单跑又绿——它按毫秒窗口确认"应该没收到"，抢 CPU 时窗口被挤破。处置：按"发→转→收"三段各查一次，条目里"要改存档"的前提先读现有结构；`run-tests.mjs` 让 `net` **独占** + 否定窗口压到 250ms。

- esbuild 打包（动态 import + 环死锁、`banner` 不打包）与"换桩后门禁晚于主包加载"、"用 resolveId 而非 alias 做打包开关"见 [`notes/tips-tooling.md`](./notes/tips-tooling.md)。
## 界面与音频

### "XX 会自动关闭"先分清两件事：**浮层被重排关掉** vs **按钮 `active` 判据混了筛选**

- 症状 A（浮层）：配方书点开后在屏幕上**闪一下就消失**，`isOpen` 为 false，`show()` 与隐藏紧挨着——关它的是"重排"。
  根因：`openRecipeBook()` 是 `show()` → `syncRecipePane()` → `applyInventoryChrome()`，而 chrome 的容器/工作站分支
  都写了 `onCloseRecipes()`。处置：**布局函数只做几何与显隐**，"关闭/销毁/清状态"放到真正的触发点
  （`openWith()` 的 `mode/容器变了` 块、`openTrade()`、玩家自己的 ✕/R），并断言"重排里不出现 `onCloseXxx`"。
- 症状 B（按钮，用户原话）："点击可合成按钮，他会跳到搜索分类，但是……按钮会自动关闭，需要再点一下才打开。"
  根因：`active` 的判据不是**点击所翻的那个位**——先写成 `leftPane === 'category' && showUnowned`（第一次点进来 `showUnowned=false`，
  必然"视图开了、按钮灭的"），改成 `leftPane === 'category'` 又变成"分类页里关不掉、仓库里永远灰着"。
  处置：**亮灭判据必须就是点击所翻的那个状态变量**（`toggle('active', this.showUnowned)`），
  特殊逻辑（比如"仓库里关着时顺手跳页"）只额外做跳页，不要参与亮灭计算；
  同一颗键在工作站那份代码里往往还有一份 `toggle('active', …)`，两处一起改。
- 适用面：任何"先 `show()` 再 `notify/sync`"的成对接口（配方书/成就/统计/暂停）与"图标键 + 状态类"（配方/创造/建造/视角）。
  **本项目在 B 上连错两轮**（先答成 A、再答成"跟视图走"），用户第三次才把口径说到"状态完全由用户控制"——
  遇到"开关类"，先问一句"这个开关代表哪个状态、由谁控制"，比读代码便宜。

### 测试断言按"字面量"匹配，文案一搬进表就会成片变红

- 症状：把界面文案接进 i18n（只换取值方式、不动行为）之后，`test:ui` 一次红了 7 条、`test:i18n` 红 3 条，
  断言原文形如 `src.includes("this.showMessage('绑定诅咒：这件装备取不下来');")`。
- 根因：这些断言当时想守的是"这条路径会给出提示"，但写法是**匹配那句中文**；
  文案搬走后源码里没有这句话了，断言必然失败——它失败的原因与"功能坏了"完全无关。
- 处置：这类断言一律改成**按文案键**匹配（`includes("t('inventory.bindingCurse')")`），
  迁移一次、之后随文案改动免疫。同一次改动里还要补一条**负向守卫**（源码字面量里不再有中文），
  否则"搬了一半"没人看得见。⚠️ 守卫自身的边界：它按**字符串字面量**判，
  所以行尾注释里的英文引号（`// 保持"按下"态`）也会被当成字面量——那种注释改用中文引号。
- 适用面：任何"文案进表 / 换模板引擎 / 改占位符命名"的重构，先 grep 一遍 `test:*` 里有没有匹配原文的断言。

### 挂在 `#hud` 里的可点元素，会被触摸端的全屏视角面吃掉点击

- 症状：按钮看得见、事件也绑上了，手指点下去毫无反应；反倒"点哪挖哪"，把身后的方块挖了一块
  （引导卡的收起键/「不再提示」、批次 95 的快捷栏都这样）。
- 根因：`#hud` 是 `pointer-events: none`，子元素靠 `pointer-events: auto` 单开；而触摸操作层
  `#touch-ui > #touch-look`（`position: absolute; inset: 0`）在 DOM 里**排在 `#hud-right` 之后**，
  两者都没有 `z-index` 时后出现的在上层，命中测试先落到视角面。
- 处置：可点元素要 `pointer-events: auto` **加** `z-index`（并加 `position: relative`，别依赖
  "flex 子项也适用 z-index"这一条细节）；新增 HUD 可点元素先问"它在 `#hud` 里还是 `<body>` 里"，
  前者一律抬层。
- 适用面：任何挂在 `#hud` / `#hud-right` 里的按钮、卡片、徽章。⚠️ 这个坑**只在触摸端暴露**
  （桌面端指针锁定期间 HUD 本来收不到事件），离线断言查不到——要兜就断言 CSS 里有 z-index。

### 固定 px 的竖排工具条在横屏必压操作键——而且会**抢走**它的点击

- 症状：手机上按跳跃毫无反应；看起来像"工具条挡住了"，实测重叠只有 32×76 —— 但工具条 `z-index: 9`、
  `#hud` 没有 z-index，那一下点击**落到了工具条上**。玩家报的是"盖住跳跃键"，实际是"跳跃键按不动"。
- 根因：尺寸写死（双列 44px + 4px 间隙 = 92×236 的竖条），而横屏只有 360~430 高；236 高 + 垂直居中
  必然跨到右下那一簇键（跳跃 76×scale，右边界 `视口宽 − (40 + 28×scale)`）。
- 处置：几何**按视口算**（`ui/buildToolbarLayout.ts` 纯函数，断言量四边 / 暂停条下沿 / 热区 ≥44）；
  形态改成"折叠态一颗 44×56 开关 + 展开态居中抽屉"——开关只占右缘 52px 宽，与跳跃键留 16px，
  抽屉居中后不再朝下长，还自带遮罩（模态 + 点遮罩即关）。
- 判据：任何贴边的竖条先算**最矮目标视口（640×360）× 最大触摸缩放（1.4×）**会不会碰到右下那一簇；
  `z-index` 高于 HUD 的元素必须确认它不吃掉底下按钮的点击（"挡住"和"抢走点击"是同一个 bug 的两种说法）。
- 适用面：左右边缘的浮动工具条、调试面板、任何 `position: fixed` 且 `pointer-events: auto` 的 HUD 层。

### 「部分图标空白」多半是缓存毒化：图集没铺像素时画一次，就永久空

- 症状：某几件方块的图标在**所有**界面（快捷栏 / 创造栏 / 分类栏）都是空的，
  切分类、重开背包都不恢复；同一屏里其它方块与物品全正常。
- 根因：主菜单阶段的图集是 `deferPaint` 的空画布。`BlockIcon` 用图集拼等轴图标并把结果按
  `blockId` 缓存（只按 `atlas.revision` 失效），于是"在铺像素之前画过的那几个方块"缓存里是
  **全透明的 34×34**，之后没有任何路径会重画。2026-10-22 实测 9 件：沙 / 原木 / 树叶 / 木板 /
  圆石 / 玻璃 / 工作台 / 箱子 / 砖块 —— 正好是 `BuildToolbar` 的图标，而它在
  `atlas.ensureUploaded()` 之前构造。
- 处置：① 进世界先 `atlas.ensureUploaded()`，**排在任何 UI 构造之前**；② `blockIconCanvas`
  在 `!atlas.isPainted` 时返回 null（宁可空一次，也不写坏缓存）；③ 进世界 `clearBlockIconCache()`
  让旧会话的坏条目自愈（不必刷新页面）。
- 判据：先分清"画不出来"（图集空 / 缺贴图 → 全量都空）还是"没重画"（固定几件、重开无效）——
  后者一律查缓存与构造次序。离线只能断言"代码形状"（`test:textures` 的 4 条），
  视觉复验要在浏览器里量 canvas 的不透明像素数。
- 适用面：任何"按 id 缓存位图"的 UI（方块图标、成就图标、小游戏素材）＋任何"构造时就画图"的组件。

- **小游戏柱子的间距必须大于方块边长**：`gapMinStart 1.4` + `blockSizeStart 1.8` 时两根柱子互相重叠，整屏只剩一根——玩家看不到"要跳哪"，而逻辑与单测全绿（纯几何重叠，断言覆盖不到）。判据：`gapMin > blockSizeStart`，用截图或按分数扫一遍生成结果。
- **宿主在 stage 上 `setPointerCapture` 会把 click 也重定向到 stage**：结算面板的"再来一局 / 退出"因此点不动，而 `document.elementFromPoint` 明明命中按钮。修法是面板那层 `pointerdown / pointerup / pointermove` 全部 `stopPropagation`，宿主就不会拿捕获。这类问题纯逻辑测试永远发现不了，只能靠 Playwright 真点。
- **绝对定位元素别塞进同样 absolute 的 HUD 容器**：`.jump-hint` 挂进 `.jump-hud`（两者都是 absolute）后会相对 HUD 定位，跑到左上角与分数叠在一起；挂到 stage 上才是"底部居中"。

### 同名 CSS 规则在文件后段又写了一遍，前面"看起来已经统一"的写法被悄悄覆盖

- 症状：首页主/次按钮在横屏块里已经写成 44/44，手机上仍然一高一矮（主 52 / 次 44）。
- 根因：同一个选择器 `body.touch-mode .world-secondary` 在这个 5000 行的 `index.html` 里
  **被写了三遍**（横屏适配块、触摸端按钮尺寸块、PC 宽屏块）。后出现的规则赢，
  前两处改得再整齐也无效；而且读代码时只会先看到第一处。
- 处置：改尺寸前先 `grep -n "选择器名"` 列全所有同名规则，把常量收到**一条共用规则**上
  （例如 `.world-primary, .world-secondary { min-height: 52px; }`），其余处只留字号/内边距。
  断言也要钉"共用规则里有这个值 + 后面不再出现旧值"，否则下次又会被覆盖。

## 渲染与光照

### `meshBoxes` 与 `collisionBoxes` 是两套盒子，判据不能互相照抄

- 症状与根因：门一开就"整扇消失"（碰撞侧"开着不挡"是对的，渲染侧抄了同一条就成了"开着不画"，`doorBox` 的开态几何一行都执行不到）。
- 处置：渲染盒永远返回 `[doorBox(state)]`、碰撞盒保留 `isDoorOpen ? [] : ...`；断言要同时盯两侧。适用所有"同一形状两种物理行为"的方块（门/活板门/睡莲），**别复制粘贴另一侧**。

### canvas 程序化贴图：工厂要可注入，UV 要按**法线**重映射

- 症状：特殊方块的手绘贴图只有截图能验（"四类里两类画成同一张"肉眼里只是"都是深灰"）；换成圆柱后顶面贴上了侧面图。
- 根因与处置：① `document.createElement` 直接调 → node 里测不了；改成注入 `CanvasFactory`，测试传一个**记录 2D 调用序列**的假上下文，
  "画了几张/多大/顶面在左格还是右格/四类指纹是否撞车"就全可断言。② 一张图集两格时按顶点下标切 UV → 方盒与圆柱顶点顺序不同必然错位；
  改看法线：`|normal.y| > 0.9` → 左格 `[0,.5]`，其余 → 右格 `[.5,1]`。
- 适用面：所有"用 canvas 现画美术"的地方。判据写"调用了哪些绘制原语"，不写"看起来像"。

### 不透明物体按"由近到远"排：不写深度的贴片会被本体盖掉

- 症状：给方块顶面加的白色中心点**完全看不见**（元素在、材质白色、位置在顶面正上方 2mm）。
- 根因：`depthWrite: false` 只禁止写深度、不禁止被别人遮；不透明物体按**由近到远**渲染，白点先画完就被顶面整片盖住（它自己没写深度，深度测试帮不上忙）。
- 处置：`transparent: true` + `renderOrder = 3`（方块 1、阴影 0、波纹 2 同一套序号），任何"贴在不透明表面上的薄片"都要这两条。
- 同源教训：**"看不见"类问题离线断言几乎抓不到**——元素在、文本对、E2E 全绿。这一批还有一例：分数 HUD 的 `top: 6%`
  在横屏 390 高下只有 23px，被宿主顶栏（8px + 36px 按钮 + z-index 4）盖住。凡是要模仿现成产品，收尾前必须真看截图。

### "每屏重建"的 3D 场景：动画进度按位置保留、配色按身份取

- 症状：① 每跳一次整屏方块一起"弹一下"；② 每跳一次所有方块**换色**（像世界重新上色）。
- 根因：每落地都 `setBlocks(前后 4 块)` 重建网格——入场动画没有记忆；配色又用了"这一屏列表里的下标"，列表整体前移一格就换色。
- 处置：`Map<位置键, age>` 把入场进度带过重建；颜色改 `BlockSpec.colorIndex`（传方块 id）。
  断言写静态的（`blockColorAt(this.palette, spec.colorIndex)`），因为"每跳一次重新上色"截图里看不出来。

### 平衡模拟的误差模型必须与机制同构（相对误差 ≠ 绝对误差）

- 症状：把间距从"绝对格数"改成"边长的 1.15~1.9 倍"之后，`jump:balance` 里"手抖玩家"500 局一局不死
  （300 跳触顶），而阈值一个字没改。
- 根因：模拟里的手抖是 `间距 × (1 ± 24%)` 的**相对**误差；间距缩到 1.15~1.9 个边长后 24% 只有 0.24 格，
  永远小于半块边长 → 数学上不可能失败（注释写的却是"±0.18 格"的绝对口径）。
- 处置：改成 `间距 ± 0.55 格`（= 0.1s 的按早/按晚 × maxDistance / maxCharge）。判据：误差来源是**按的时间**就写绝对误差，
  是**估的距离**才写相对；两者在同一套参数下会给出相反的难度结论。改的是模型不是阈值——阈值一动脚本只剩"能跑通"的价值。
- 追加（批次 20261024-1331）：**起跳点也算模型的一部分**。把规则改成"从实际落点 `stand` 起跳"之后，
  模拟器仍按"方块中心 → 方块中心"算瞄准距离；所有断言照样绿，只有输出数字悄悄从 23.1 跳掉到 11.8 跳。
  改规则语义时，凡是自带一份"规则副本"的脚本（平衡模拟、E2E 反算按压时长、截图脚本）都要一起改，
  并让离线测试用"读脚本源码 + 与 config 数值比对"钉住（`MAX_DISTANCE` / `MAX_CHARGE_MS`）。

### 3 块取景在横屏下**纵向**吃紧，别按"宽度撑满"写断言

- 症状：给"一屏 3 块"写断言"横向撑满视口 ≥ 60%"，实测只有 33%，看着像取景错了。
- 根因：方块沿前进方向往上排，正交视锥的半高由纵向包络决定，半宽 = 半高 × aspect；
  横屏 844×390 的 aspect 是 2.16，所以横向永远"富余"，纵向才是绑死的那一维。
- 处置：断言量**纵向**（`(maxY − minY) / (top − bottom) ≥ 0.6`），横向只用来判断"方块占屏宽别太小"。
  竖屏反过来（纵向富余），所以这类断言必须写明按哪一维量。

## 交互与方块操作

### 红石是"整体重算"，别让它按当前电平覆盖玩家的手动状态

- 症状：手动开关木门只响一声、门却"半扇"（上半透明、下半还挡着），再点也不恢复；
  活板门、栅栏门同样开不了。
- 根因：`RedstoneEngine.applyOpenableLoad` 每次 `recompute` 都把负载按**当前输入电平**重写一遍，
  而手动开合**不改变电平**；`main.ts#toggleDoor` 又是"先写下半、再写上半"的两次写入，各触发一次
  重算 → 下半被关回、上半留下来。再叠上"开着的门不画"，就成了"上半透明"。
- 处置：负载改成**电平沿触发**（记上次电平，只有变化才动门）；`onBlockChanged` 顺手删掉"已不是
  可开合方块"的记录；换维度清空（坐标只在维度内有意义）。判据：**状态只由输入决定**的（灯、活塞）
  才可以无脑重写；**玩家也能改状态**的（门类，以后还有别的）必须认"变化"。
- 适用面：任何"无状态重算 + 玩家可改状态"的组合（红石负载、告示牌、命令方块…）。

## 地形生成

### 出生点用 `Math.random` / 只认试投中心点，会把"种子随机"变成"看起来都一样"

- 症状（两件事同源）：① 玩家反馈"不管什么种子，进去都是草地 + 树 + 海边 + 远处高山"；
  ② 想改成随机出生后，5 个种子全落在雪原/冰刺。
- 根因：① 旧版按 `起伏×1000 + 群系偏好×80 + 离原点距离` 打分取最优，
  任何种子都会收敛到"离原点最近的一块平原"——地形本身是随机的，**出生点的审美是写死的**。
  ② 改成半径 1024 的面积均匀试投后，落进海里的点全部被海平面判据淘汰，
  能通过的只剩"本来就在海平面以上的高地"，而高地在这个生成器里偏冷。
- 处置：随机源**必须由世界种子派生**（`new Random(seed).nextDouble`，否则同种子重进换出生点）；
  试投点不达标时先在 8/16 格环上找最近的岸（`flatSpotNear`），再判群系；
  全落空才退回原来的网格扫描兜底。断言要覆盖"跨种子不同 / 同种子一致 / 落点高于海平面"三条。
- 适用面：任何"随机挑一块地"的玩法（结构选址、刷怪点、出生点）都要同时满足
  **可复现**（种子派生）与 **别让筛选条件本身变成偏置**。

### 把"整屏尺寸的面板"塞进半栏容器，等于自己造一个假 bug

- 症状：配方书改成嵌进背包左栏之后，列表里出现**对不上的数字**、点格子**没反应**；
  换回整屏那一层立刻正常。
- 根因：那块面板是按整屏排的（标签栏 + 搜索框 + 12 列网格 + 分页 + 熔炼表），
  CSS 里虽然有一段 `.recipe-panel.embedded` 把它压进 7 列，但**数据侧没跟着变**：
  分页大小、格子尺寸、详情行都还按整屏算，于是格子错位、点到的不是看到的那一格。
- 处置：判断"这块面板能不能嵌进半栏"的唯一标准是**它的排版是不是为半栏写的**。
  为整屏写的一律不嵌（宁可让它盖上来，靠自己的 ✕ 关闭）；真要嵌，先把它拆成
  "容器 + 内容"两层，让内容按容器宽度重排，再加断言。
- 适用面：任何"嵌进左栏/侧栏"的复用（配方书、统计、成就、地图）。

### `position: fixed` 的底部 dock 不参与父级网格，面板会正好压在它上面

- 症状：背包在"某些屏幕"上被挤到快捷栏上面一点点（不同机型压得多少不一样）。
- 根因：`#inventory-screen` 是 `grid-template-rows: 1fr auto`，而快捷栏 dock 是
  `position: fixed` —— 它**脱离文档流**，第二行高度塌成 0，面板就按整屏高度居中。
- 处置：给父层加 `padding-bottom = dock 高度 + env(safe-area-inset-bottom)`（本项目 62px），
  不要指望网格自动避让。断言要盯"让位值里含 `safe-area`"，否则刘海屏又会压回来。
