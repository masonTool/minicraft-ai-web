# 设计决策 · NOTES

> 这份文档回答**「当时是怎么做的、为什么这么做」**——按**模块 / 主题**组织，不按时间。
> 时间线在 `DONE.md`，动手前要避开的坑在 `EXPERIENCE.md`。
>
> 判据只有一句：**「下一批还会被这个问题绊到」→ 写这里；「只有这批需要知道」→ 只写 `DONE.md`。**
>
> 谁写、什么时候写：AI，**收尾时**自问一次"这批有没有改变后续做法 / 约定的决策"。
> 有就补一节，没有就跳过——**不要写「本批无新增决策」这类占位**，占位会让人以为读过。
>
> 边界：单节 ≤ 15 行。超了说明它该独立成 `notes/<模块>.md`，并在这份留一行索引。
> 只写**结论与理由**，不要贴大段代码（代码在 git 里，会漂）。

## 格式

````md
## <模块/主题> · <决策一句话>（批次 24）
- 做了什么：具体到文件 / 函数，别写"优化了一下"
- 为什么：不这么做会付出什么代价，试过什么不行
- 代价与边界：这个选择牺牲了什么，什么情况下不再成立
- 什么时候该重看：触发条件（需求变了 / 规模变了 / 依赖换了）
````

## 钩子日志：只给"有队列的会话"记，少而准优先于全量留痕（批次 1366）
- 做了什么：`lib.appendLog` 三处硬约束——① 队列文件不存在就直接 `return`（连日志文件都不建）；
  ② 时间戳用本地时区（`localStamp()`，文件头写一次 `本地时间 +08:00`）；③ 与上一行内容相同就跳过。
  关键节点统一前缀（`会话初始化` / `回灌` / `拦截` / `隔离` / `自测通过|失败` / `放行`），
  并且 `auto-continue` 在回灌那一轮**不归零** `state.count`。
- 为什么：日志唯一用途是回答"续跑为什么停了"。原来每次 Stop 都会记 `放行 · 工作区干净`、
  纯问答会话每轮记 `放行 · 本会话尚未创建队列`，长跑几百轮后真事件被淹；UTC 时间还得脑内换算才能对上屏幕时间。
- 代价与边界：**日志不再能证明"钩子被调用过"**（纯问答会话零痕迹）——那条路改用 `HANDOFF §4`
  的手动喂事件；"相邻去重"也意味着同一件事连发多轮只留第一次的时间点（轮次在涨的事件不受影响）。
- 什么时候该重看：想事后统计"每轮耗时 / 放行比例"这类指标时 → **别把逐轮日志加回来**，另写结构化事件流。

## 续跑成没成的判据：`拦截` 与 `回灌` 必须成对出现（批次 1366）
- 做了什么：`queue-init` 命中回灌时记「回灌 · UserPromptSubmit · 第N轮任务反馈已到达客户端」，
  `auto-continue` 记「拦截 · Stop 第N轮 · 递任务 …」，两条放一起读。
- 为什么：钩子只能"请求"客户端开新回合（见 `EXPERIENCE.md`）。只有「拦截」= 递了但没被接住；
  两条都有且 `第N轮` 递增 = 链路通。以前没有这条判据，只能靠肉眼翻时间戳猜。
- 代价与边界：`第N轮` 的语义是"**用户上次发言之后**的第几轮"，不是"历史总轮次"——用户一说话就归零。
- 什么时候该重看：客户端换了续跑策略（真能连跑多轮）时，这条判据仍然成立，只是会更频繁地看到成对出现。

## `[发现]` 的优先级：排在所有用户任务之后（批次 1355 查证）
- 做了什么：确认 `auto-continue.mjs` 挑任务的顺序是"先找非 `[发现]` 的条目、`[发现]` 兜底"（`pickNext` 里那条正则）。
