# 设计决策 · NOTES

> 这份文档回答**「当时是怎么做的、为什么这么做」**——按**模块 / 主题**组织，不按时间。
> 时间线在 `DONE.md`，动手前要避开的坑在 `EXPERIENCE.md`。
>
> 判据只有一句：**「下一批还会被这个问题绊到」→ 写这里；「只有这批需要知道」→ 只写 `DONE.md`。**
>
> 谁写、什么时候写：AI，**收尾时**自问一次"这批有没有改变后续做法 / 约定的决策"。
> 有就补一节，没有就跳过——**不要写「本批无新增决策」这类占位**，占位会让人以为读过。
>
> 边界：单节 ≤ 15 行。超了说明它该独立成 `notes/<模块>.md`，并在这份留一行索引。
> 只写**结论与理由**，不要贴大段代码（代码在 git 里，会漂）。

## 格式

````md
## <模块/主题> · <决策一句话>（批次 24）
- 做了什么：具体到文件 / 函数，别写"优化了一下"
- 为什么：不这么做会付出什么代价，试过什么不行
- 代价与边界：这个选择牺牲了什么，什么情况下不再成立
- 什么时候该重看：触发条件（需求变了 / 规模变了 / 依赖换了）
````
