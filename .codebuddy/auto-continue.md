## 批次 99：联机套件偶发红灯（O15）+ 一条假断言

> 上一批（94~98）在收 M18（移动端）时，我在体检里记下过 O15：`npm run test:net`

> 而那个习惯一养成，真红也会被当成偶发。

- [x] B99-1 **根因**：服务端是**刚 spawn 出来的**（Node 起进程 + 绑端口 + 建 handler），
  而测试的 `wait()` 只等 1500ms——机器一忙就超时；更糟的是 `join` 可能在
  服务端 handler 就绪**之前**发出去，那条消息永远没人接
- [x] B99-2 三条修法：① `wait` 默认超时 1500 → **4000ms**；
  ② 新增 `joinAndWaitWelcome()`（第一次等 2.5 秒没回就**重发一次 join**——
  真实玩家重连也是这个行为）；③ 就绪等待 5 → 10 秒，并把"等 100ms 再断言"
  换成"等那条广播真的到"（`await bob.wait('block')`）。连跑 3 次全绿
- [x] B99-3 **顺带抓到一条假断言**：`check('非法坐标不会写进世界快照', true)`——
  第二个参数写死 `true`，**永远不会红**，标题说的那件事根本没验。现在让一个新玩家
  加入并断言它的快照里没有那条非法改动（真验）
- [x] B99-4 核了一遍其它依赖时序的断言：钓鱼咬钩/雨声那些都已经是"注入随机源 +
  推进固定刻度"，没有"睡一会儿再看"的写法 ✓
