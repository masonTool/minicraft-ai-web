## 批次 99：联机套件偶发红灯（O15）+ 一条假断言

## 批次 130：移动端渲染降级策略（N7：动态分辨率 / 限帧 / 粒子总量）

> 用户点名："优化手机端的显示性能"。手机的问题不是"算不过来"，而是**发热降频之后
> 越玩越卡**——所以这一批做的不是"让某一帧更快"，而是**一整套降级旋钮**
> （N6 只做了自适应视距，TASKS N7 一直空着）。
>
> 做法上有两件事：① 把 N6 那套写在主循环里的策略**收进纯模块**（从此可断言）；
> ② 补上另外三个旋钮。

- [x] B130-1 **`core/world/PerfPolicy.ts`**（新模块，纯逻辑）：把 N6 的自适应视距收进来，
  并定下**优先级**——掉帧时**先降分辨率**（0.5~1.0，一次 0.1），分辨率到底了才降视距；
  有余量时**反过来**（先还视距、最后还分辨率）。阈值（22ms/17ms）、冷却（降 3~4 秒、
  升 8~10 秒）、地板（分辨率 0.5、视距 4）与视距上限（玩家设定值）全在这里
- [x] B130-2 **动态分辨率**：`applyResolutionScale()` 落到渲染器上。
  ⚠️ `setSize(w, h, false)` 的第三个参数**必须传 false**——传 true 会把 canvas 的 CSS 尺寸
  也乘上倍率，那就成了"把画面缩小"而不是"降分辨率"；分辨率一变还要通知粒子系统
  （它的点尺寸是按设备像素算的）
- [x] B130-3 **限帧**（`maxFps`：0 / 30 / 60）：主循环里"这一帧来得太早就不画"，

- [x] B130-4 **粒子总量**（`ParticleSystem.setBudget`）：与"粒子强度"分工不同——
  那一档管"每次撒多少"，这一条管"场上最多同时多少"；`burst` 里按剩余空间**少撒几颗**
  （不是整簇不撒，也不是踢掉旧粒子）；启动时也应用一次（否则存档里的设置要等开一次设置才生效）

  默认值刻意选成手机优先（两档自适应都开、不限帧）
- [x] B130-6 **验收**：`tools/perf-acceptance.js` 重写成"先分辨率、再视距"的顺序检查 +

- [x] B130-7 新套件 `test:perfpolicy`（**34 条**）：降级/恢复的**顺序**、地板与上限、

## 批次 175：世界边界（TASKS K12 收口）

- [x] B175-6 门禁：新套件 `test:border` **51 条**（默认值/夹取/读档容错/越界距离/伤害档位/推回/命令/渲染）；
