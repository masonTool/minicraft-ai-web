# 自动继续队列

> 由 `.codebuddy/hooks/auto-continue.mjs`（Stop 钩子）读取。
> 只要这里还有 `- [ ]` 或 `- [~]` 的条目，AI 在每轮结束时会自动继续，不会停下来等确认。
>
> - 紧急刹车：`touch .codebuddy/auto-continue.off`
> - 恢复自动：`rm .codebuddy/auto-continue.off`
> - 单次会话次数上限：环境变量 `AUTO_CONTINUE_MAX`（默认 12）

## 批次 25：性能——高度图缓存（C6）+ 补齐定点基准（A8）

> 用户要求"性能优化"。**先量再改**：现在能称得上"基准"的只有区块生成耗时与

- [x] `core/world/Heightmap.ts` + `Chunk` 接入（**C6**）：

      方块变化时只维护那一列（往上长是 O(1)，挖掉地表才回扫）
      —— 实测：建表 3 µs/列、查询 **38 ns/次**；与"逐格往下扫"逐列对照结果完全一致
- [x] **刷怪的热点**：`MobSpawner.trySpawnPassive` 原来是从玩家高度往下**逐格找草方块**——
      一次尝试最多 16 列 × 330 格（基准里量到单列 **381 次读**、一个周期约 **6000 次**）。
      改用高度图后建过表就是 0 次。用**操作预算断言**把这条锁住（`getBlock` 调用次数上限），

      确定性预算断言并进 `npm test`（现在是 **41 套**）
      —— 顺带做了**网格化指纹**（顶点位置/贴图坐标/顶点光照/索引数压成一个常量），
      任何改动都要重跑：**"快了但画错了"是最糟的结果**
- [x] **顺手把网格化自身的分配去掉**（基准逼出来的第一个真优化）：

      现在坐标直接算、光照打包成整数、4 个角写进复用对象（合并成组时**拷一份**）。
      **23.1 → 17.2 ms/区块，指纹不变**
