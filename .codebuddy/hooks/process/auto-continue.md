# 自动继续队列

> 由 `.codebuddy/hooks/auto-continue.mjs`（Stop 钩子）读取。
> 只要这里还有 `- [ ]` 或 `- [~]` 的条目，AI 在每轮结束时会**自动继续做下一条**，不停下来等确认。
>
> - 位置：`.codebuddy/hooks/process/`（**进度文档，进仓库**）
> - 日志与计数状态：`.codebuddy/hooks/logs/`（每轮都变，已 gitignore）
> - 紧急刹车：`touch .codebuddy/auto-continue.off`；恢复：`rm .codebuddy/auto-continue.off`
> - **没有轮次上限，也没有上下文上限**：队列不清空就一直跑（用户要求）
> - 上下文用量只在每轮反馈里**显示**给人看，**不作为停下来的理由**；
>   要停下问人只走一条路——AI 自己发现风险就弹窗（见《上下文用量：只显示，不叫停》）

---

## 怎么排一个长跑队列（长时间运行前必读）

**目录分工**（都在 `.codebuddy/hooks/` 下）：

| 目录 | 放什么 | 进仓库？ |
| --- | --- | --- |
| `hooks/process/` | 本文件（队列）+ 归档 + `batch-seq` | ✅ 要 review 的进度 |
| `hooks/logs/` | `auto-{continue,commit}.log`、`*.state.json` | ❌ 每轮都变，已 gitignore |
| `.codebuddy/*.off` | 刹车开关 | ❌ 同上 |

混在一起的后果很具体：日志每小时往 `git status` 冒一次，`auto-commit` 每轮都把它当
"未提交改动"拦住，最后只能靠关钩子收场。日志另有轮转（超 512KB 转存 `.1`）。

**约束**（轮次无上限、队列长度放开、上下文也不设限）：

| 约束 | 数值 | 超了会怎样 |
| --- | --- | --- |
| 队列行数 | 5000 行（仅防意外，如误粘大文件） | `npm run check` 失败 |
| AI 自插任务 | 同时最多 5 条 `[发现]`（`AUTO_CONTINUE_DISCOVERED_LIMIT`） | 满了必须等你过一遍 |
| 单条连续重试 | 5 轮（`AUTO_CONTINUE_BLOCK_AFTER`） | 自动标 `[阻塞]` 跳过，并上报给你决策 |
| ~~上下文水位~~ | ~~150k~~ | **已取消**：只显示不叫停，见《上下文用量：只显示，不叫停》 |

## 一条任务做不完会怎样（卡死保护）

`[~]` 也算待办，所以一条做不完的任务会被**无限递回来**。没有闸的话，
一条做不动的任务会烧光上下文、交接、再烧，永远走不到后面的条目。

**机制**：同一条连续出现 5 轮还没勾掉 → 自动改成 `- [阻塞]`：

```
- [阻塞] <原条目内容一字未动>
```

然后：

1. **跳过它**，把下一条递给你继续做（队列不会因为一条卡住而停摆）；
2. **要求 AI 如实上报**：哪一条、试过什么、卡在哪个报错/断言/文件行号，
   并给出**三个选项**（改描述继续做 / 删除 / 先留着），但**不许替你决定**；
3. 被标 `[阻塞]` 的条目**不会再被选中**（`remaining` 与选下一条都会跳过它）。

**这是"上报"，不是"放弃"**——你的决策权没有被脚本替掉。处理方式：

| 你的决定 | 怎么做 |
| --- | --- |
| 改描述继续做 | 把 `[阻塞]` 改回 `[ ]` 并修好描述，下一轮自动重试（计数从零开始） |
| 删掉 | 直接删这一行 |
| 先留着 | 不动它，它会一直待在那儿，不干扰后面的任务 |

计数存在 `.codebuddy/hooks/logs/auto-continue.state.json` 的 `attempts` 里
（按"去掉勾选标记后的正文"做指纹），跨会话保留。

**一条 = 一个可独立验证的改动**（能单独 commit）。写清「改哪个文件 / 验收标准」，
**不要写"接着上面那个继续"**——上下文压缩后前面的细节会丢。

**每条做完必须自己勾 `[x]`**（开始时先改 `[~]`）。钩子**只读不写**队列——
它只负责"还有没有 `[ ]`"，勾选是 AI 干的。忘了勾就会反复做同一条。

**长跑前先 `git commit` 一次**，留个干净起点，出事好回滚。

## AI 可以自己插任务（有硬条件）

AI 在**动手过程中**撞见的问题，往往比排好的任务更值钱——改物理时发现水里没断言、
写界面时发现某个分支是死代码。这类信息**只有动手才能拿到**。

所以允许它插，但格式与证据是必须的：

```
- [ ] [发现] <一句话说清是什么>：<哪个文件/哪条断言暴露的> → <怎么算做完>
```

**三条硬条件**（钩子每轮都会重申）：

1. **必须是真实撞见的**，条目里写证据（文件行号 / 断言失败 / 实测现象）。
   不许写"我觉得""可能""顺便优化一下"这类没有证据的。
2. **只能插，不能删改用户排的任务**——已有的 `[ ]` 一条都不许动、不许重排。
3. **插完必须在回复里明说**"我插了一条：[发现] …，因为 …"，让你能看见并否决。

额度：同时最多 5 条 `[发现]`（`AUTO_CONTINUE_DISCOVERED_LIMIT` 可调）。
满了钩子会要求"先干完手上的活，让用户过一遍已有发现"——这道闸是防
"为了有活干而发明任务"（本项目真实踩过：队列空了自己编条目，看起来在推进，其实空转）。

## 上下文用量：只显示，不叫停（2026-10-21 改）

**上下文没有限制**，钩子不会因为你跑得久就让你停下。

这个结论是改出来的，原来不是这样：旧版会在 `input_tokens` 超过 150k 时切进「收尾交接」，
让你把活收干净、生成一段提示词、自己复制去开新会话。那套逻辑已经**整块删除**，两个原因：

1. **打断节奏**：它按 token 数停，跟手上这条做没做完毫无关系。而"换个会话说"本身
   就要重读一遍文档，代价不比省下的那点上下文小。
2. **会自我死锁**：平台把钩子反馈当成一条新的用户消息回传（`UserPromptSubmit`），
   钩子按"人工介入"把轮次清零，于是每轮都重新判"超限"，同一个交接指令连发十几轮。
   更糟的是卡死保护（连续 5 轮标 `[阻塞]`）**因此永远触发不了**——轮次一直被清零。
   实测连续撞了 20 轮才靠外部打断。

现在只剩一件事：**用量会显示在每轮反馈的第一行**（`当前上下文约 NNk tokens`），
供你自己判断要不要换会话。要不要换是**你的决定**，脚本不替你决定。

### 那什么时候该停下来问人？

按**风险**问，不按 token 数问。钩子每轮都会把这条规则递给 AI：

撞到下面任一情况，AI 必须用 `AskUserQuestion` **弹窗**把选项摆给你，等你选完再继续：

| 该弹窗的情况 | 例子 |
| --- | --- |
| 不可逆的破坏 | 删数据 / 改存档格式 / 改公开接口 / 强制推送 |
| 会波及其他批次 | 要动的文件是另一条的地盘；改动会让已通过的断言变红 |
| 多种合理做法且取向不同 | 性能 vs 一致性、对齐原版 vs 修复体验 |
| 需求本身有歧义 | 条目能理解成两个意思，做错要返工 |
| 超出这条的范围 | 做完发现必须顺手改一大片没在这次范围内的东西 |

**弹窗要求**：给 2~4 个**具体**选项（不是"继续/停止"），每个写清代价，推荐项放第一位。
选完立刻执行，不再来回确认。

**这正是"队列写在文件里"的价值**：进度不靠会话记忆，靠文件。换会话零成本——
需要换的时候你自己一眼就能看出来，不需要脚本催。

## 流程（一轮照着走，别凭记忆）

> 顺序有意义：**先写纯逻辑与断言，再接界面与主程序**——反过来，界面里那些"看起来对"
> 的分支会掩盖规则本身的错。

1. **读队列**：本文件「当前队列」的第一条；长期缺口看 `TASKS.md` 的 `[~]`。
   别从 `TASKS.md` 从头扫（几百条，扫一遍就没预算做正事了）。
2. **定范围**：一条 `[ ]` 拆成"能一批收掉"的（数据 / 规则 / 一处 UI / 一套断言）。
   拆不动的（群系、结构、多人大改）留回队列，并写一句"为什么这批不做"。
3. **纯逻辑先行**：`core/...` 里写不引 DOM / 不引世界的模块，
   规则里的每个"如果"都能单独断言。
4. **数据链路四处一起补**：`restoreStack` / `stackExtras` / `sameExtras` / `Transfer.cloneExtras`。
   漏第一处＝读档丢数据，漏第三处＝两件不同的东西被并堆吞掉一件，漏第四处＝漏斗搬一趟丢数据。
5. **接界面**：面板挂 `<body>`、层叠层 12、Esc 自己收、关闭时调 `onClose` 交还输入权；
   手机横屏是主场景（面板封顶、内容自滚、按钮固定底部）。
6. **自测 → commit → 勾 `[x]`**：`npm run check:fast` 通过、实测数据写进 commit message，
   然后单独提交（中文 message），再把条目改 `[x]`。
7. **只做一条就停**：下一条由钩子在下一轮递给你，不用连着做。
