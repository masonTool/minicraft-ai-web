# 文档冲突时以谁为准（批次 614 定）

用户原话：「哪个更权威就采用哪一个的，但是另外一个的信息也不要丢，能够合并到一起最好。」

## 权威顺序（从高到低）

1. **`TASKS.md` 的 `[x]` / `[~]` / `[-]`** —— 唯一事实来源。派生数字（进度/套数/配方数/
   提交数/覆盖率/差异）一律由脚本生成，手抄必漂。
2. **`.codebuddy/auto-continue.md`** —— "进行中"的唯一口径（Stop 钩子读它）。它同时承载
   批次记录与下一步候选。
3. **`HANDOFF.md`** —— 接手必读的状态快照与硬性约定，行数上限 340（`npm run audit:docs` 卡）。
4. 其余摘要类文件（`PENDING.md`、临时清单）—— **没有权威性**，只允许"贡献正文里没有的信息"。

## 两条硬规矩

- **同一个事实不写两处。** 写两处必然有一处漂：本轮就抓到 `PENDING.md` 手抄
  `281/9/3` + 提交号 `8ba4261b` 全部过期，而它是个孤儿（全仓零引用）。处理方式是
  **把独有信息（阻塞原因/卡点）并入权威文件，然后删掉摘要文件**，不是两边都更新。
- **合并后先跑门禁，不要先信自己写的话。** `npm run check` 里的 `audit:tasks` /
  `audit:coverage` / `audit:diffs` / `audit:docs` 会当场抓住漂移。本轮它们抓到了：
  ① 覆盖度台账过期（物品 1127→1128、生物 70→71、配方 744→745，**改前就红**，不是本轮引入）；
  ② HANDOFF 超行数上限（382 → 340，压缩表格不动事实）；
  ③ 提交总数 1234 → 1238。
